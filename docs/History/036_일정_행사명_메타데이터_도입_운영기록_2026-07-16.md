# 일정 행사명 메타데이터 도입 운영 기록

## 배경

기존 일정은 회차 열의 헤더 값으로 날짜·시작·종료·GPS 정책을 관리하고, 헤더 셀 Note 전체를 장소 안내로 사용했습니다. 이 구조에서는 운영진과 학생이 회차의 실제 행사 성격을 구분하기 어려웠고, 이미 저장된 장소 메모를 행사명으로 오인하거나 덮어쓸 위험이 있었습니다.

## 결정

헤더 값은 기존 시간/GPS 계약을 그대로 유지하고, 헤더 셀 Note에 버전이 있는 구조화 메타데이터를 저장합니다.

```text
[CloudClub 일정 메타 v1]
행사명: {선택 행사명}
장소안내:
{기존 장소 안내}
```

일반 텍스트로 저장된 과거 Note는 전부 장소 안내로 해석하고 행사명은 빈 값으로 둡니다. 구조 마커가 있더라도 필수 행 구성이 올바르지 않으면 일반 Note로 취급해 내용을 숨기지 않습니다.

## 동시 수정 보호

일정 저장 전후의 원본 Note가 달라졌는데 행사명 또는 장소 안내를 명시적으로 수정하려는 요청이면 `SCHEDULE_CHANGED_RETRY`로 중단합니다. 반대로 `eventNameProvided`가 없는 과거 관리자 요청은 잠금 이후 최신 Note를 그대로 보존하므로 새 행사명을 지우지 않습니다.

## UI 반영

- 일정 추가·수정 모달에 선택 행사명 입력을 추가했습니다.
- 기존 일정의 행사명을 다시 불러와 수정할 수 있습니다.
- 일정 표와 달력 셀에 행사명을 표시합니다.
- 관리자와 학생의 현재/다음 출석 회차 안내에 행사명을 포함합니다.

## 검증

- 구조화 Note 왕복과 legacy Note 호환
- 동시 수정 충돌 및 구버전 요청의 최신 Note 보존
- 행사명 80 Unicode 문자 경계와 줄바꿈 거부
- 관리자 모달 입력·복원·저장 payload 정적 계약
- 변경 JavaScript 구문 검사

## 배포 및 롤백

GitHub Pages는 Apps Script 배포 전에도 독립적으로 배포할 수 있습니다. 이 경우 새 입력은 보이지만 실제 행사명 저장과 API 응답 반영은 변경된 Apps Script 배포 후 활성화됩니다. 문제가 생기면 Pages는 직전 artifact로, Apps Script는 운영자가 직전 정상 배포 버전으로 되돌립니다.
