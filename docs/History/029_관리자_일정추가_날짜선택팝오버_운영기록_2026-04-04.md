## 1. 배경
목록 중심 일정 관리 구조로 정리한 뒤에도 `새 일정` 버튼은 내부적으로 오늘 날짜 기준 모달을 바로 열거나, 모달 안에서 다시 날짜를 고르게 하는 흐름에 가까웠다. 운영자는 일정 추가 전에 날짜를 먼저 고르는 작은 진입 UI를 원했고, 캘린더 카드로 내려가지 않고도 목록 카드 상단에서 바로 날짜를 고를 수 있는 흐름이 필요했다.

## 2. 변경 결정
- `새 일정` 버튼은 작은 날짜 선택 팝오버를 먼저 연다.
- 팝오버 안의 `type="date"` 입력으로 날짜를 고르면 같은 일정 모달이 열린다.
- `오늘` 버튼과 `이 날짜로 열기` 버튼을 함께 둔다.
- 팝오버는 바깥 클릭이나 `Escape`로 닫힌다.
- 기존 모달 내부 날짜 입력과 저장/삭제 로직은 그대로 유지한다.

## 3. 구현에서 실제로 바뀐 것
### 3-1. 진입점
- 목록 카드 헤더에 날짜 선택 팝오버를 추가했다.
- `새 일정` 버튼은 이제 오늘 날짜 모달 직행이 아니라 팝오버 토글 역할을 한다.

### 3-2. 상호작용
- 날짜 선택 즉시 새 일정 모달을 열 수 있다.
- `오늘` 빠른 버튼으로 오늘 날짜를 바로 적용할 수 있다.
- 모달이 열리면 팝오버는 자동으로 닫힌다.

### 3-3. 문서/체크리스트
- 관리자 가이드, 변경 맵, 회귀 체크리스트에 날짜 선택 팝오버 흐름을 반영했다.

## 4. 검증 / 회귀 체크
### 자동 검증
- `node --check`로 수정한 프런트 파일 문법 확인
- `node scripts/doublecheck_static_guard.js`
- `git diff --check`

### 수동 검증
1. `새 일정` 버튼 클릭 시 작은 날짜 선택 팝오버가 뜨는지
2. 날짜 선택 또는 `오늘`/`이 날짜로 열기` 클릭 시 해당 날짜 기준의 새 일정 모달이 열리는지
3. 팝오버 밖 클릭과 `Escape`로 닫히는지
4. 목록 `수정`, 캘린더 `+`, 새 일정 팝오버 경로가 모두 같은 일정 모달을 재사용하는지
