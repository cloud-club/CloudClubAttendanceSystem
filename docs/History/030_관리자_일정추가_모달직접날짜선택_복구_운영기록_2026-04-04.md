## 빠른 흐름도
```mermaid
flowchart LR
  A["새 일정 버튼 클릭"] --> B["기존처럼 일정 모달 즉시 오픈"]
  B --> C["모달 안 날짜 필드/달력 버튼으로 날짜 선택"]
  C --> D["선택 날짜 기준으로 저장"]
```

## 1. 배경
`새 일정` 버튼에 작은 날짜 선택 팝오버를 붙인 뒤, 실제 사용감이 오히려 나빠졌다는 피드백이 바로 나왔다. 운영자가 기대한 것은 `새 일정`을 누르면 예전처럼 바로 팝업이 뜨고, 그 팝업 안에서 날짜를 고를 수 있는 흐름이었다.

## 2. 변경 결정
- 헤더 아래 작은 날짜 선택 팝오버는 제거한다.
- `새 일정` 버튼은 다시 기존처럼 일정 모달을 바로 연다.
- 대신 새 일정 모달 안의 날짜 필드를 유지하고, 새 일정 진입 시 그 날짜 picker를 바로 띄워 날짜 선택이 자연스럽게 시작되게 한다.
- 목록 `수정`과 캘린더 `+`가 쓰는 같은 일정 모달 흐름은 유지한다.

## 3. 구현에서 실제로 바뀐 것
- `새 일정` 버튼용 인라인 날짜 팝오버 마크업/CSS/상태/이벤트를 제거했다.
- `openTodayScheduleCalendarModal()`은 다시 새 일정 모달을 직접 여는 흐름으로 되돌렸다.
- 새 일정 모달 진입 시 기존처럼 모달이 먼저 보이고, 그 안의 날짜 선택기가 자연스럽게 열리도록 유지했다.

## 4. 검증 / 회귀 체크
### 자동 검증
- `node --check`로 수정한 프런트 파일 문법 확인
- `node scripts/doublecheck_static_guard.js`
- `git diff --check`

### 수동 검증
1. `새 일정` 클릭 시 헤더 아래 별도 팝오버가 아니라 일정 모달이 바로 뜨는지
2. 새 일정 모달 안에서 날짜를 자연스럽게 선택할 수 있는지
3. 목록 `수정`, 캘린더 `+`, 새 일정 버튼이 모두 같은 일정 모달 흐름을 공유하는지
