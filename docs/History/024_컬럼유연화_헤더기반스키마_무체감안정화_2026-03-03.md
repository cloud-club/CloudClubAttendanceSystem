# 024. 컬럼 유연화(헤더 기반 스키마) 무체감 안정화 기록 (2026-03-03)

## 배경
운영진이 시즌 시트에 커스텀 칼럼(예: `클둥대백과 작성`)을 중간 삽입하는 운영이 발생했고, 기존 일부 경로가 고정 컬럼 위치(A~L/M+) 가정에 결합되어 있었습니다.

요구사항은 다음 두 가지였습니다.
1. 사용자/운영자 체감 동작은 기존과 동일(무체감)
2. 출석 날짜 컬럼이 이동/삽입되어도 파싱 및 출석 처리 무결성 유지

## 핵심 변경
1. **스키마 해석 메타 확장**
- `resolveMemberSchemaFromHeaders`에 `mode`, `profileEndColIndex`, `customProfileColumns`를 추가해 감사/진단 가시성을 강화했습니다.

2. **시즌 업데이트 경로의 고정 인덱스 결합 완화**
- update 대상 시트를 `isV2` strict 여부로 차단하던 조건을 완화하고, 필수 헤더(Name/Season/Phone/Email) 존재 기준으로 변경했습니다.
- 기존 row 업데이트를 `1~12열 일괄 setValues`에서 **필드 매핑 기반 셀 업데이트**로 변경했습니다.
- 신규 row append 시 대상 시트 실제 열 구조를 존중해 표준 필드만 채우고 커스텀 칼럼은 공란으로 보존합니다.

3. **출석 세션 보호 판정 정밀화**
- `hasAttendanceData` 판정 범위를 `sessionStartColIndex~끝`에서 **실제 세션 헤더 컬럼 집합** 기준으로 변경했습니다.
- 커스텀 칼럼 값으로 보호 판정이 과대 계산되는 문제를 방지했습니다.

4. **문서 정합화**
- README/Wiki/History 체크리스트를 “표준 헤더 권장 + 런타임 헤더 기반 유연 처리”로 정렬했습니다.

## 비변경 원칙
- public/admin API action/파라미터/응답 계약은 변경하지 않았습니다.
- 출석/현황/랭킹/대시보드/수료/유고/수동승인 플로우는 동작 불변을 유지합니다.
- 시즌 import(update)는 운영 공지된 별도 리스크 영역으로 분리 관리합니다.

## 운영 체크 포인트
1. 날짜 세션은 열 위치보다 헤더 패턴(`YYYY-MM-DD-HH:MM[~HH:MM]`)이 정합성 기준입니다.
2. 필수 헤더(Name/Season/Phone/Email) 누락 시 update를 차단합니다.
3. 커스텀 칼럼은 update 시 자동 보존 정책을 적용합니다.
