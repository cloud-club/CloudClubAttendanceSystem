# 관리자 로그인·푸터·출석 조회·일정 관리 컴팩트 보정 운영 기록

작성일: 2026-07-15  
범위: `web/*`, `DESIGN.md`, 관리자 컴팩트 레이아웃 회귀 테스트  
배포 계층: GitHub Pages만 해당

## 1. 요청 배경

관리자 로그인 화면과 관리자 탭을 실제 운영 화면 기준으로 다시 확인한 결과, 세 가지 사용성 문제가 함께 확인되었습니다.

1. 시스템 연락처가 잘못된 도메인 조합으로 표시되어 있었습니다. 운영 연락처 정본인 `cloudclub2022@cloudclub.kr`로 통일했습니다.
2. 로그인 화면의 푸터가 콘텐츠 높이에 따라 중간에 떠 보였습니다. 공식 Cloud Club 페이지의 하단 구성과 동일한 정보 구조를 유지하면서, 짧은 화면에서는 뷰포트 아래에 붙고 긴 화면에서는 콘텐츠 뒤에 자연스럽게 이어지도록 바꿨습니다.
3. 관리자 `출석현황`과 `일정 관리`는 정보량이 많아도 한눈에 비교할 수 있도록 보조 영역과 표의 밀도를 낮춰야 했습니다.

## 2. 결정 사항과 구현 범위

### 2.1 연락처와 공식 푸터

- `web/admin/index.html`, `web/privacy.html`, `web/terms.html`의 기존 연락처를 모두 `cloudclub2022@cloudclub.kr`로 변경했습니다.
- 로그인 푸터는 [Cloud Club 공식 페이지](https://www.cloudclub.kr/)의 하단 정보 구조를 기준으로 재구성했습니다.
  - 공식 설명 문구
  - Cloud Club 로고 링크
  - GitHub·Instagram·LinkedIn·YouTube 원형 아이콘 링크
  - 개인정보 처리 안내·이용약관 링크
  - Contact 영역의 이메일과 Instagram
  - `© 2026 Cloud Club. All rights reserved.`
- 공식 페이지의 Gmail 주소는 외부 사이트의 별도 연락 채널이므로 시스템 운영 연락처로 복사하지 않았습니다. 이 관리자 시스템에서는 요청된 `cloudclub2022@cloudclub.kr`를 사용합니다.

### 2.2 푸터 하단 고정

- 문서 `body`를 세로 flex 컨테이너로 만들고, `.container`가 남은 높이를 채우도록 했습니다.
- `.site-footer`는 `margin-top: auto`와 고정된 flex 크기를 사용합니다.
- 이 방식은 콘텐츠가 짧을 때만 푸터를 뷰포트 아래로 밀어 붙이고, 콘텐츠가 길어질 때는 푸터가 문서 마지막에 놓이는 자연스러운 스크롤 동작을 보존합니다.
- 모바일에서는 공식 푸터 정보가 세로로 쌓이므로 페이지 전체 높이가 뷰포트보다 커지는 것이 정상입니다. 이 경우에도 푸터는 문서의 마지막에 위치합니다.

### 2.3 출석 조회·순위 컴팩트 배치

- `출석 현황 조회`와 `출석률 순위`를 `.status-secondary-row` 하나로 묶었습니다.
- 데스크톱에서는 두 카드를 같은 행에 배치하고, 조회 폼은 전화번호 입력과 조회 버튼을 한 줄로 배치합니다.
- 순위 표의 내부 여백과 글자 크기를 줄여 카드가 과도하게 높아지지 않도록 했습니다.
- 1199px 이하에서는 가독성과 터치 영역을 위해 한 열로 되돌립니다. 이는 모바일에서 가로 스크롤을 만들지 않기 위한 의도적인 반응형 경계입니다.

### 2.4 일정 관리

- Google Sheets 바로가기 버튼을 초록색 success 계열로 강조했습니다.
- 바로가기 옆에 안내 버튼을 추가하고, 클릭 시 다음 내용을 동일한 초록색 톤의 note로 표시합니다.
  - `구글 클라우드 클럽 공식 구글 계정으로만 접근 가능합니다.`
  - `가능한 한 구글 시트를 직접 수정하지 말아 주세요. 데이터 구조가 깨질 수 있습니다.`
- 좌측 일정 표의 설명 문구를 짧게 줄이고, 표 제목을 `직접 종료`, `장소`처럼 압축했습니다.
- 날짜·시각이 긴 시작 라벨은 목록에서 `MM-DD HH:mm`으로 표시해 한 줄에 보이도록 했습니다. 원본 회차 키와 상세 편집 값은 그대로 유지됩니다.
- 1600px 이상에서는 좌측 일정 목록과 우측 캘린더를 같은 grid 행에 배치하고 두 카드의 높이를 동일하게 맞춥니다. 1600px 미만에서는 기존 단일 열 반응형 구조를 유지합니다.

## 3. 책임 경계와 배포 판단

- 이번 변경은 `web/*`와 문서·회귀 테스트만 수정했습니다.
- `Appsscript/*`의 API 라우팅, 권한, 시트 읽기·쓰기 계약은 변경하지 않았습니다.
- 따라서 정상 배포 경로는 GitHub Pages 배포이며 Apps Script 새 배포나 코드 재업로드는 필요하지 않습니다.
- Pages workflow가 `web/shared/env.js`에 `APPS_SCRIPT_WEB_APP_URL`을 주입하는 현재 구조는 그대로 유지됩니다.

- 모바일 390×844: 푸터가 문서 끝에 위치하고 가로 넘침 없이 공식 푸터 정보가 세로로 표시됨
- 데스크톱 1798×1140 일정 fixture:
  - 일정 좌우 카드 높이 각각 945px로 동일
  - 일정 표 `scrollWidth`와 `clientWidth`가 767px로 동일
  - 시작 시각이 `07-01 13:30`으로 한 줄 표시
  - Sheets 버튼이 초록색으로 보임
- 안내 버튼 클릭: `aria-expanded=true`, 안내 note가 표시됨
- 안내 버튼 재클릭: `aria-expanded=false`, note가 다시 숨겨짐
- 출석현황 fixture:
  - 보조 카드 두 개가 한 행에 배치됨
  - 두 카드 높이 각각 572px로 동일
  - 조회 폼이 입력과 버튼의 한 줄 grid로 표시됨

로컬 정적 서버에서는 workflow가 주입하는 `API_BASE_URL`이 없기 때문에 인증 초기화 오류 안내가 표시됩니다. 이는 Pages 배포 환경의 API URL 누락을 뜻하는 것이 아니라, 로컬에서 `env.js` 주입을 하지 않은 상태라는 검증 한계입니다.
