## 1. 배경
`Code.gs`(대형 단일 파일)와 `web/admin/admin.js`(장문 단일 파일) 중심 구조는 수정 범위 예측과 장애 원인 추적을 어렵게 만들었습니다. 특히 운영 중 인증/권한/시즌 데이터 이슈가 한 번에 섞이면, 어떤 계층에서 실패했는지 분리하기 어렵다는 문제가 반복되었습니다.

이번 라운드는 기능 추가가 아니라 운영 안정성 회복이 목표였습니다. 사용자/운영자 체감 기능은 그대로 두고, 내부 구조와 장애 경로 차단만 수행하는 방향으로 결정했습니다.

## 2. 변경점 요약
### 2-1. 구조 전환(리팩터링)
1. 백엔드 소스를 `Appsscript/*` 도메인 파일로 분할했습니다.
- 엔트리: `Appsscript/00_entry_api.gs`
- 권한/상수: `Appsscript/01_constants_access.gs`
- 인증/관리자: `Appsscript/10_auth_admin.gs`
- 출석/대시보드/일정/가변값/수료/업로드/공통 유틸로 분리
2. 관리자 프런트를 `web/admin/scripts/*` 도메인 파일로 분할했습니다.
- `window.AdminApp` 네임스페이스 유지
- 인라인 핸들러 호환을 위해 `99_compat_handlers.js` 유지
3. Apps Script 파일 간 `import/export`는 도입하지 않았습니다.
- GAS V8 전역 스코프 공유 특성을 사용해 함수 분할만 수행
- 운영 복잡도 증가 없이 기존 호출 모델 유지

### 2-2. 긴급복구(출석 장애)
1. 장애 원인 A: 관리자 출석 경로 토큰 불일치
- `session/ranking/attendance/status` 호출에서 `adminToken` 누락 시 과거 시즌에서 `UNAUTHORIZED` 발생
2. 장애 원인 B: 배포 런타임 함수 누락
- `collectSessionsFromSheet` 누락 시 학생/관리자 출석 조회 경로가 내부 오류로 중단
3. 복구 조치
- 관리자 출석 호출을 `season + adminToken` 공통 파라미터로 정렬
- 인증 오류는 `handleUnauthorizedError` 우선 처리로 게이트 복귀
- 백엔드에 `assertRuntimeIntegrity` 추가
- `apiInfo.runtimeChecks` 추가로 필수 함수 존재 여부를 즉시 진단 가능하게 확장

## 3. 공개 API/인터페이스 영향
| 항목 | 변경 전 | 변경 후 | 비고 |
|---|---|---|---|
| 외부 API 액션/파라미터/응답 스키마 | 기존 계약 | 동일 | Breaking change 없음 |
| 관리자/학생 UI 동선 | 기존 동선 | 동일 | 체감 기능 변경 없음 |
| `apiInfo` 응답 | 운영 메타 정보 | `runtimeChecks` 추가 | 비파괴 진단 확장 |

## 4. 데이터/권한/운영 정책 영향
1. 권한 정책
- 최신 시즌 공개 액션은 기존 정책 유지
- 과거 시즌 조회는 `adminToken` 필수 정책을 명문화
2. 운영 정책
- 배포 이상 징후 시 `apiInfo.runtimeChecks`를 1차 확인 항목으로 고정
- `SERVER_INTEGRITY_MISSING`는 코드 버그보다 배포 정합성 문제로 우선 분기
3. 배포 정책
- 같은 deployment 재배포(Edit)를 기본값으로 유지해 `exec` URL 안정성 확보
- 새 deployment로 URL 변경 시 Secret 동기화가 필수

## 5. 리스크와 대응
1. 리스크: 인라인 핸들러 단절
- 대응: `99_compat_handlers.js`로 기존 전역 함수명 호환 유지
2. 리스크: 시즌/토큰 파라미터 누락 회귀
- 대응: 출석 관련 호출의 공통 파라미터 경로 고정 및 점검 절차 문서화
3. 리스크: 배포 시 일부 함수 누락
- 대응: `assertRuntimeIntegrity` + `apiInfo.runtimeChecks` + 동일 deployment 재배포 우선
4. 리스크: 분할 후 운영 추적성 저하
- 대응: Wiki 핵심 4개 문서와 History 인덱스를 `Appsscript/*` 기준으로 동기화

## 6. 검증 시나리오
1. 정적 검증
- `node --check web/admin/scripts/*.js`
- 인라인 핸들러 이름과 `window.*` 브리지 함수 매칭 확인
2. API 계약 검증
- `health`, `apiInfo`, `session`, `ranking`, `attendanceDashboardSummary`, `attendanceDashboardDrilldown`, `graduationReport`, `seasonImport*` 경로 계약 동일성 확인
3. 권한/시즌 검증
- 최신 시즌 공개 조회 정상
- 과거 시즌 무토큰 호출 시 `UNAUTHORIZED` 확인
- 과거 시즌 + 관리자 토큰 호출 성공
4. 런타임 무결성 검증
- `apiInfo.runtimeChecks` 전 항목 `true`
- 누락 시 `SERVER_INTEGRITY_MISSING` 분기와 재배포 절차 확인

## 7. 배포/롤백 기준
1. 롤아웃
- Apps Script 반영/재배포
- `apiInfo` 및 역할별 canary 확인
- Pages 반영 후 관리자/학생 스모크 점검
2. 롤백
- 프런트는 직전 커밋 기준 즉시 복귀 가능
- 백엔드는 이전 deployment 버전으로 즉시 복귀
- URL 변경 배포를 했다면 Secret 동기화 상태를 함께 롤백 점검

## 9. 운영 교훈/후속 과제
1. 구조 리팩터링은 기능 변경 없이도 장애 확률과 복구 시간을 줄일 수 있습니다.
2. 인증/시즌 정책은 코드뿐 아니라 런북과 점검표에 같이 반영되어야 재발을 줄일 수 있습니다.
3. 후속 과제는 문서 기반 점검을 자동화(`apiInfo.runtimeChecks` 캡처/검증 자동화)하는 것입니다.
