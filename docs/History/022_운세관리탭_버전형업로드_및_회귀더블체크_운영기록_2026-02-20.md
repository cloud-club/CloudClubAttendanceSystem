## 1. 배경
기존 운세는 `Appsscript/91_fortune.gs`에 하드코딩되어 있어, 운영자가 문구를 바꿀 때 코드 수정과 재배포가 필요했습니다. 또한 변경 이력 보존이 어려워 과거 문구 복원이 번거로웠습니다.

이번 변경의 목표는 다음 두 가지를 동시에 만족하는 것이었습니다.

1. 운세 운영 자동화
- 관리자 페이지에서 CSV/XLSX 업로드 또는 직접 편집으로 저장
- 저장 전 미리보기/검증으로 1차 오류 차단

2. 기존 사용감 불변
- 학생/운영자의 기존 핵심 동선(출석, 현황, 일정, 유고, 수료, 시즌업로드 등)은 체감 변화 없이 유지
- 신규 기능 영향은 운세 탭과 운세 응답 경로로만 국소화

## 2. 변경점 요약
### 2-1. 프런트 변경
1. 관리자 탭에 `운세 관리`를 추가했습니다.
- 위치: `일정 관리` 다음, `유고 처리` 이전
- 입력 방식 3종 동시 지원: `CSV`, `XLSX`, `직접 편집/붙여넣기`
2. 업로드 전 1차 검증/미리보기 UI를 추가했습니다.
- 빈값 제거, 길이(1~200자), 중복 문구 검증
- 오류/경고/유효 건수 요약 + 저장 버튼 게이트
3. 다운로드/재업로드 흐름을 추가했습니다.
- 현재본/과거 버전 각각 `CSV`/`XLSX` 다운로드
- 버전 선택 후 편집기로 재로딩 가능
4. 구버전 백엔드 호환성 차단을 추가했습니다.
- `apiInfo.supportedActions`에 `fortune*` 미노출 시 탭 내부에서만 차단 안내

### 2-2. 백엔드 변경
1. 신규 Admin 액션 6종을 추가했습니다.
- `fortuneVersionList`, `fortuneVersionGet`
- `fortuneUploadBegin`, `fortuneUploadChunk`, `fortuneUploadFinalize`, `fortuneUploadAbort`
2. 저장 모델을 `전체 교체 + 버전 스냅샷 보존`으로 확정했습니다.
3. 런타임 운세 로딩을 `current 저장본 우선 + builtin fallback`으로 구현했습니다.
4. 업로드 finalize 단계에서 서버 재검증을 수행합니다.
- 빈값/길이/중복/0건 저장 차단
- `baseVersionId` 충돌 검사 + `LockService` 동시성 제어

### 2-3. 보안 변경
학생 운세 렌더링에 `escape`를 적용해 동적 문구 저장 이후에도 HTML 주입이 실행되지 않도록 보강했습니다.

### 2-4. 검증 체계 변경
회귀 더블체크 게이트를 문서화하고, 신규 기능 외 기존 사용감 불변을 배포 전후 기준으로 검증하도록 고정했습니다.

## 3. 공개 API/인터페이스 영향
| 항목 | 변경 전 | 변경 후 | 비고 |
|---|---|---|---|
| Admin 액션 | 운세 전용 액션 없음 | `fortuneVersionList/Get`, `fortuneUploadBegin/Chunk/Finalize/Abort` | 모두 `ACTION_ACCESS_ADMIN` |
| `apiInfo.supportedActions` | `fortune*` 미포함 | `fortune*` 포함 | 프런트 호환성 가드 기준 |
| `apiInfo.apiVersion` | 이전 버전 | 증가 | 배포 식별용 |
| 운세 런타임 로딩 | builtin 하드코딩만 사용 | 저장본 current 우선 + builtin fallback | 저장본 없으면 기존 동작 유지 |
| 학생 운세 렌더링 | escape 누락 | escape 적용 | XSS 리스크 완화 |

## 4. 데이터 모델/시트 정책
신규 보조 시트는 아래와 같습니다.

1. `/_fortune_versions`
- `version_id`, `created_at`, `created_by_email`, `source_type`, `row_count`, `is_current`, `note`
2. `/_fortune_entries`
- `version_id`, `row_no`, `fortune_text`
3. `/_fortune_upload_meta`
- `upload_id`, `staging_sheet_name`, `status`, `created_at`, `updated_at`, `created_by_email`, `expected_rows`, `received_rows`
4. 동적 스테이징 시트
- `_fortune_stg_<id>` 생성/삭제

운영 정책은 다음으로 고정했습니다.

1. 저장 단위는 항상 전체 교체
2. 과거 버전은 스냅샷으로 계속 보존
3. 런타임은 current 저장본 우선, 없으면 builtin fallback
4. 업로드 전/후 검증 이중 적용(클라이언트 1차 + 서버 finalize 재검증)

## 5. 권한/RBAC 반영
1. 운세 액션군은 모두 `admin` 권한으로 추가했습니다.
- `super`와 `season_admin` 모두 저장/다운로드 가능
2. 운세 탭은 Super 전용 탭이 아닙니다.
- 기존 `SUPER_ONLY_TABS` 경계(`variables`, `seasonImport`, `adminUsers`)는 유지
3. 운세는 전역 운영 데이터로, 시즌 스코프 제한을 적용하지 않습니다.

## 6. 더블체크 게이트 운용 절차 요약
신규 기능 반영 시 아래 순서로 회귀를 점검합니다.

1. 정적 영향 분석
- 기존 액션 case 로직 변경 금지(신규 `fortune*` case 추가만 허용)
- 기존 탭 핸들러/권한 경계 불변 확인
2. API 계약 회귀 비교
- baseline 대비 기존 액션 응답 스키마/에러코드 diff 검사
- 허용 diff는 `apiInfo.apiVersion`, `supportedActions`의 `fortune*` 추가만 허용
3. 역할별 E2E 스모크
- 학생, season_admin, super 핵심 동선 체감 불변 확인
4. 구버전 호환성
- `fortune*` 미지원 백엔드에서 운세 탭만 차단되고 나머지 탭 정상 동작 확인
5. 성능/운영 게이트
- 로드/탭 전환 체감 지연이 baseline 대비 허용 범위 내인지 확인

## 7. 검증 시나리오
1. 학생 출석 성공/실패/시간종료/오입력 흐름이 기존과 동일하게 동작한다.
2. 학생 운세 출력이 escape 처리되어 HTML 주입이 실행되지 않는다.
3. season_admin/super의 기존 탭 기능이 기존과 동일하게 동작한다.
4. 운세 탭에서 CSV/XLSX/직접 편집 입력 후 검증/미리보기/저장이 정상 동작한다.
5. 빈값/중복/길이 초과 데이터는 저장이 차단된다.
6. 운세 버전 생성 후 과거 버전 다운로드/재업로드가 가능하다.
7. 구버전 백엔드 연결 시 운세 탭만 미지원 차단되고 전체 앱은 정상 동작한다.
8. 기존 액션 스키마는 화이트리스트 외 diff가 없다.

## 8. 배포/롤백 기준
1. Gate A: API 계약 회귀 통과 전 배포 금지
2. Gate B: 역할별 스모크 통과 전 배포 금지
3. Gate C: 구버전 호환성 통과 전 배포 금지
4. 즉시 롤백 트리거
- 기존 액션 스키마/에러코드 변경
- 기존 탭 기능 장애
- 인증 canary 실패
- 콘솔 치명 오류 지속 발생

## 10. 운영 교훈/후속 과제
1. 신규 탭 추가 시 기존 사용감 불변 검증을 병행해야 실제 운영 안정성이 유지됩니다.
2. 버전 보존은 운영 복구 시간을 크게 줄이므로, 향후 운영 데이터 도메인에도 동일 패턴 적용 가치가 있습니다.
3. 후속 과제로 운세 버전 비교(diff) 뷰와 변경 사유(note) 강제 입력을 검토할 수 있습니다.
