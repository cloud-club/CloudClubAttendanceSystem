flowchart LR
  A["문제 징후 확인"] --> B["원인 후보 분리"]

## 목적
이 문서는 시트 스키마 v2(`A~L 회원 프로필 + M+ 출석세션`) 운영에서 배포/마이그레이션/장애 대응을 같은 순서로 수행하기 위한 체크리스트입니다.

## A. 배포 전 체크 (Pre-flight)
| 점검 항목 | 운영자 | 개발자 | 완료 기준 |
|---|---|---|---|
| 시즌 탭 규칙 | `season_nn` 확인 | alias 매핑 코드 확인 | 시즌 선택/URL/시트명 일치 + 학생 기본 URL `latest` 고정 |
| v2 헤더 12개 | A~L 헤더 순서 확인 | `MEMBER_V2_SHEET_HEADERS` 확인 | 오탈자/누락 0건 |
| 세션 시작열 | M열 이후 확인 | 세션 파서 동작 확인 | `sheetSchemaAudit.sessionStartColIndex >= 12` |
| Phone 슈퍼키 | 중복 검사 | duplicate 에러 처리 확인 | 중복 0건 |
| 필수값 결측 | Name/Season/Phone/Email 점검 | 감사 API 결과 확인 | 결측 허용 범위 내 |
| API URL/버전 | 관리자 화면 연결 확인 | `apiInfo`, `health` 확인 | 최신 배포 응답 |
| 운영 배포 정합성 | Apps Script 배포 선택 확인 | `API_BASE_URL`과 배포 URL 대조 | 운영 `exec` URL 단일화 |
| Web App 실행 주체 | `다음 사용자 인증 정보로 실행` 확인 | 배포 실행 계정 점검 | `나(cloudclub2022@gmail.com)` |
| Debug helper 준비 | `Code.gs`의 `__authorizeExternalRequest()` 존재 확인 | 함수 호출 경로/권한 팝업 가이드 확인 | 장애 시 즉시 실행 가능 |
| OAuth scope canary | 로그인 전 canary URL 확인 | canary 명령/응답 코드 기록 | `AUTH_SERVER_SCOPE_MISSING` 미발생 |
| 런타임 URL 일치 | `env.js` 실시간 값 확인 | deployment URL 교차검증 | `API_BASE_URL == 운영 deployment URL` |

## B. 시즌 탭 수동 마이그레이션
| 순서 | 작업 | 성공 기준 |

| 1 | 스프레드시트 복제본 생성 | 복제본 URL 확보 |

| 9 | 1건 출석 스모크 테스트 | 기록/조회/랭킹 정상 |

## D. 배포 후 E2E (회귀)
| 기능 | 테스트 절차 | 기대 결과 |
|---|---|---|
| 출석 처리 | valid phone 1건 체크 | 정시/지각 판정 + 색상 적용 |
| 상태 조회 | 동일 phone 조회 | seasonLabel/통계 정상 |
| 랭킹 | 시즌 랭킹 조회 | 정렬/평균오프셋 정상 |
| 수동 승인 | manualApprove 실행 | 실제 승인시각 기록 + 회차 경계 자동보정 + 메모 기록 + 중복 보호 |
| 유고 처리 | excusedSet preview/override | 2단계 확인 동작 |
| 수료 판정 | graduationReport 조회 | 세션 오프셋 오류 없음 |
| 멤버 조회 | members 응답 확인 | 12필드 데이터 노출 |
| 관리자 인증 | Google OAuth 로그인 + `_admins` 화이트리스트 | 미등록 Gmail 차단 / 등록 관리자만 접근 |
| 관리자 서버 권한 | `authGoogleLogin(dummy)` 재확인 | scope 오류 없이 토큰 검증 단계 코드 반환 |
| 관리자 계정 분기 | Super/Admin/User 각 계정 로그인 | Super 진입 / Admin 시즌 제한 / User 거절 |
| 과거 시즌 URL 보호 | `/web/student/latest/?season=season_nn` 접속 테스트 | 비관리자 차단 후 latest 이동 / season_admin 본인 시즌만 허용 / super 전체 허용 |

### D-1. 계정별 인증 결과 기록 템플릿
| 테스트 시각 | 계정 | 기대 Role | 실제 결과 | 응답 코드 | 스크린샷/로그 링크 | PASS/FAIL |
|---|---|---|---|---|---|---|
| 예시 | `cloudclub2022@gmail.com` | `super` | 관리자 진입 성공 | `OK` | 링크 | PASS |
| 예시 | `thquddnr123@gmail.com` | `season_admin` | 시즌 범위만 접근 | `OK` | 링크 | PASS |
| 예시 | `cybecho.proxy@gmail.com` | `user(거절)` | 로그인 후 거절 | `AUTH_ADMIN_NOT_REGISTERED` | 링크 | PASS |

## E. 장애 우선순위
| 우선순위 | 증상 | 1차 확인 | 2차 조치 |
|---|---|---|---|
| P1 | 출석 기록 실패 | `sheetSchemaAudit`, session 헤더 | 복제본 롤백 + 배포 롤백 |
| P1 | phone 식별 충돌 | duplicate rows 확인 | 운영자 수동 정리 |
| P1 | session 인식 실패 | M+ 헤더 패턴 확인 | 헤더 수정/복구 |
| P2 | 업로드 finalize 실패 | `_import_meta` 상태 확인 | abort 후 재시도 |
| P2 | 관리자 로그인 직후 `UrlFetchApp.fetch` 권한 오류 | Web App 배포 설정 / 권한 승인 여부 확인 | `__authorizeExternalRequest()` 실행 + 동일 배포 재배포 + canary 재검증 |
| P2 | 운영 URL과 배포 ID 불일치 | `env.js` API URL vs Manage Deployments URL 대조 | 운영 배포 단일화 + GitHub Secret 재저장 |
| P2 | UI 표기 불일치 | `seasonLabel || grade` 경로 확인 | 프런트 재배포/캐시 제거 |
| P3 | optional 필드 누락 | 디버그 warning 확인 | 소스 파일/매핑 조정 |

---

## F. 롤백 기준
1. 코드 롤백: Apps Script 이전 버전 재배포.
2. 데이터 롤백: 사전 복제본에서 시즌 탭 복원.
3. 운영 롤백: `activeSheet`를 안정 시즌으로 전환.
4. 즉시 롤백 조건: P1 발생(출석 실패/phone 식별 오류/session 인식 실패).
5. 인증 장애 롤백: 이전 정상 `exec` URL로 Secret 복원 후 Pages 재배포.

## G. 증빙 아카이브 체크
| 증빙 항목 | 최소 내용 | 저장 위치(권장) |
|---|---|---|
| canary 실행 로그 | 실행 명령, 응답 코드, PASS/FAIL | 운영 티켓/노션 |
| Apps Script 배포 설정 캡처 | Execute as, access, deployment URL | 운영 티켓/노션 |
| 권한 승인 이력 | `__authorizeExternalRequest()` 실행 시각/계정 | 운영 티켓/노션 |
| Secret 변경 이력 | `APPS_SCRIPT_WEB_APP_URL` 변경 시각 | 운영 티켓/노션 |
| Actions 배포 로그 | workflow run id, 성공 상태 | 운영 티켓/노션 |

## H. 실행 메모
1. 운영자는 반영 전후 `sheetSchemaAudit`를 반드시 실행합니다.
2. 개발자는 신규 기능 배포 시 `Code.gs` 문법 체크 + 프런트 문법 체크를 함께 실행합니다.
3. 인증 장애는 `019` 런북 Gate 순서대로만 복구합니다.
4. import/update 운영 이슈는 `013`, `014`, `015` 문서를 기준으로 판단합니다.
