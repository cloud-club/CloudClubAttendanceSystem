# 관리자 UI 컴팩트 앱 셸 전면 개선 운영 기록

## 빠른 결론
관리자 화면의 기존 색상·카드 톤과 10개 탭 기능은 유지하면서, 사용자가 `클라우드 출석지 관리 시스템` 영역으로 지칭한 기존 `CLOUD CLUB`·`출석체크 관리자 시스템` 대형 히어로를 제거했다. 그 자리는 높이 60px의 공통 상단바로 바꾸고 로고를 왼쪽, 시스템 이동 메뉴를 오른쪽에 배치했다. 데스크톱은 최대 1760px의 가로 공간을 사용해 카드들을 2~3열로 배치하고, 모바일은 같은 메뉴 DOM을 오른쪽 드로어로 전환해 기존 세로 스크롤 사용성을 유지한다.

이번 변경은 `web/*` 관리자 UI, 테스트, 문서만 수정한다. `Appsscript/*` API·RBAC·시트 로직은 변경하지 않으므로 이 변경 자체로 사람이 Apps Script를 다시 올릴 항목은 없다. 운영 반영은 `gh-pages` 푸시와 GitHub Pages 워크플로우로 끝난다.

## 1. 변경 배경과 관찰값
기존 관리자 진입 화면은 대형 제목, 장식, 설명과 별도 탭 블록이 세로 공간을 연속으로 사용했다. 브라우저 기준 첫 운영 카드가 나타나는 위치는 다음과 같았다.

| 뷰포트 | 기존 첫 카드 시작 | 개선 후 첫 카드 시작 | 변화 |
|---|---:|---:|---:|
| 375×667 | 1,250px | 334px | 916px 단축 |
| 768×1024 | 1,228px | 324px | 904px 단축 |
| 1280×900 | 800px | 181px | 619px 단축 |
| 1920×1080 | 757px | 181px | 576px 단축 |

기존 캡처에서는 장식 요소가 뷰포트보다 100px 넓은 문서 폭을 만들기도 했다. 개선 후 375·768·1280·1920px 네 뷰포트 모두 `document.scrollWidth === window.innerWidth`를 확인했다.

## 2. 설계 결정
### 2.1 단일 상단바
- 기존 히어로의 대형 영문·한글 제목, 구분선, 장식용 구름을 제거했다.
- 기존 Cloud Club 로고 자산과 짙은 남색·하늘색 톤은 유지했다.
- 로고와 `Cloud Club 출석 관리` 표기는 왼쪽에 고정하고, 10개 시스템 이동 탭은 오른쪽부터 이어지게 배치했다.
- 데스크톱 상단바 높이는 60px, 모바일은 56px로 제한했다.

### 2.2 탭 DOM을 복제하지 않는 반응형 메뉴
데스크톱용 메뉴와 모바일용 메뉴를 각각 만들면 권한에 따른 탭 숨김, 활성 상태, 지연 로딩 상태가 서로 어긋날 가능성이 있다. 따라서 `#adminTabNav` 하나만 유지한다.

- 데스크톱: 상단바 오른쪽의 가로 메뉴
- 모바일: 화면 오른쪽에서 열리는 폭 320px 이하 드로어
- 공통: `role="tablist"`, 탭별 `aria-controls`, 패널별 `aria-labelledby`
- 키보드: 좌우 Arrow, Home, End로 탭 이동 및 활성화
- 닫기: Escape, 배경 클릭, 탭 선택
- 포커스: 열 때 활성 탭으로 이동하고 닫을 때 메뉴 버튼으로 복귀

### 2.3 가로 공간을 탭 성격에 맞게 사용
모든 탭을 동일한 열 수로 강제하지 않았다. 카드 수와 폼·표의 폭을 기준으로 다음 중단점을 적용했다.

| 중단점 | 적용 예시 |
|---:|---|
| 1000px | QR 코드 관리 2열 |
| 1200px | 출석현황·운세 관리 2열, 세션/시즌 유틸리티 가로 배치 |
| 1440px | 출석하기·수료 판정·시즌 업로드·관리자 관리 다열 |
| 1600px | 일정 관리의 목록·캘린더 카드 다열 |
| 768px 이하 | 모든 탭 단일열, 모바일 드로어, 세로 스크롤 |

관리자 컨테이너는 최대 1760px, 카드 간격 16px, 기본 조작 높이 44px을 사용한다. 정보 밀도는 높였지만 모바일 터치 영역은 줄이지 않았다.

## 3. 구현 파일과 책임
- `web/admin/index.html`: 공통 상단바, 단일 탭 DOM, 모바일 드로어 마크업, 탭별 반응형 그리드와 밀도 토큰
- `web/admin/scripts/07_admin_shell.js`: 탭 ARIA 상태, 키보드 이동, 모바일 메뉴, 인증 전후 앱 셸 상태
- `web/admin/scripts/03_dom_refs.js`: 인증 게이트와 앱 셸 노출 동기화
- `web/admin/scripts/10_auth.js`: 역할별 탭 표시 이후 접근성 상태 재동기화
- `web/admin/scripts/20_attendance.js`: 기존 `openTab()` 지연 로딩 이후 활성 탭·모바일 메뉴 상태 동기화
- `web/admin/scripts/90_bootstrap.js`: 제거된 장식 구름의 빈 초기화·스크롤 감시 코드 정리
- `scripts/admin_compact_layout_test.js`: 상단바, 단일 10개 탭, 패널 ARIA, 반응형 토큰, 스크립트 순서 회귀 검사
- `scripts/run_doublecheck.sh`: 공통 doublecheck의 Gate 0-B에 관리자 앱 셸 회귀 검사 추가
- `DESIGN.md`: 관리자 전용 간격·중단점·접근성 계약 추가

## 4. 기존 동작 보존 원칙
이번 작업은 앱 셸과 정보 배치만 바꾼다.

- API URL, 액션 이름, 파라미터, 응답 계약을 바꾸지 않았다.
- `openTab()`의 탭별 지연 로딩 분기를 유지했다.
- `season_admin`은 시즌 업로드·관리자 관리가 보이지 않고, `super`는 두 탭을 사용할 수 있는 기존 권한 차이를 유지했다.
- 인증 전에는 로그인 게이트만 보이며, 인증 후에만 관리자 유틸리티와 탭 콘텐츠가 나타나는 흐름을 유지했다.
- 일정·출석·운세·시즌 업로드 등 각 도메인 스크립트의 업무 처리 로직은 수정하지 않았다.

## 5. 구현 중 발견하고 해결한 브라우저 문제
### 5.1 모바일 문서 폭 초과
닫힌 드로어를 `translateX()`로 화면 밖에 보내는 방식은 고정 요소가 포함된 합성 경계에서 문서 폭 측정에 영향을 줬다. 닫힌 상태는 화면 밖 이동 대신 `opacity`와 작은 `scaleX()`로 표현해 문서 폭을 정확히 뷰포트와 맞췄다.

### 5.2 고정 드로어의 기준 컨테이너 문제
상단바의 `backdrop-filter`가 고정 자식의 포함 블록처럼 동작해 드로어가 헤더 높이 안에 갇히는 현상을 확인했다. 관리자 상단바와 컴팩트 표면에서는 해당 필터를 제거해 드로어가 전체 뷰포트를 기준으로 표시되게 했다.

### 5.3 투명 캔버스의 검은 합성 타일
기본 상태에서 전체 화면 크기의 투명 confetti 캔버스가 일부 자동 캡처 환경에서 검은 타일로 합성됐다. 캔버스는 기본 `display:none`으로 두고 실제 축하 효과를 시작할 때만 표시하도록 바꿨다.

### 5.4 장식 구름의 가로 넘침
의미 없는 장식 SVG가 좁은 화면에서 가로 폭을 넓혔다. 화면 밀도와 기능에 기여하지 않아 마크업을 제거했다. 초기화 코드는 빈 컬렉션을 안전하게 처리하므로 별도 분기는 필요하지 않았다.

### 5.5 모바일 한국어 줄바꿈과 포커스 경계
첫 시각 검수에서 `로그/아웃`, `관리/자`, `스키/마`처럼 한국어가 음절 단위로 갈라지는 상태와 44px보다 작은 보조 버튼을 발견했다. 관리자 앱·인증·footer에 `word-break: keep-all`을 적용하고, 긴 토큰만 필요할 때 분리되도록 `overflow-wrap`을 함께 사용했다. 모바일 버튼·입력·링크·체크박스 라벨의 실제 조작 영역도 44px 이상으로 통일했다.

모바일 드로어는 열림 직후 활성 탭으로 포커스를 옮기고, Tab/Shift+Tab이 닫기 버튼과 허용된 탭 안에서 순환하도록 보강했다. Escape로 닫으면 메뉴 버튼으로 포커스가 돌아가며 1280px에서 768px로 직접 크기를 바꿔도 `aria-orientation`이 `vertical`로 갱신된다.

## 6. 검증 증거
### 6.1 자동 회귀
- `node --test scripts/admin_compact_layout_test.js`: 8개 테스트 모두 통과
- `node --check web/admin/scripts/07_admin_shell.js`: 문법 통과
- `./scripts/run_doublecheck.sh --out-dir .artifacts/doublecheck-admin-compact-final`: 정적 게이트와 관리자 앱 셸 Gate 0-B 통과
- API baseline/candidate 비교는 Apps Script를 변경하지 않은 UI 전용 작업이므로 URL 없이 생략했다.

### 6.2 반응형 시각 검증
- 10개 탭 × 4개 뷰포트 = 40개 화면 상태
- 뷰포트 캡처와 전체 페이지 캡처를 합쳐 PNG 80개 생성
- 모든 캡처에서 뷰포트 폭 일치, 알파 채널 이상 0건, 의심 검은 영역 0건
- 375×667, 768×1024, 1280×900, 1920×1080의 접촉 시트로 탭 전체를 비교
- 1280px 탭 메뉴는 `navClientWidth === navScrollWidth`와 첫 탭 완전 노출을 확인했고, Chrome viewport 캡처는 GPU 합성을 끈 재촬영에서 순검정 타일 0건을 확인했다.

원본과 개선 화면의 픽셀 유사도는 1920px 22점, 375px 17점이다. 이는 회귀가 아니라 히어로 제거와 카드 재배치라는 의도된 전면 레이아웃 변경이다. 두 비교 모두 이미지 크기와 알파 채널은 일치했다.

### 6.3 상호작용 검증
- 모바일 메뉴 열기 후 활성 탭 포커스
- Escape 닫기와 메뉴 버튼 포커스 복귀
- Arrow 키로 다음 탭 활성화 및 패널 `aria-hidden` 동기화
- `season_admin`/`super` 역할별 탭 노출과 시트 버튼 활성 차이
- 375px에서 메뉴가 열린 상태까지 문서 폭 375px 유지

실제 운영 Google 로그인과 실데이터 표·차트는 로컬 자격증명 없이 재현하지 않았다. 대신 기존 도메인 로직을 건드리지 않고, 인증 완료 상태를 모사한 브라우저 하네스로 모든 탭의 레이아웃과 권한 표시 계약을 검증했다.

## 7. 배포 범위와 수동 작업
### 이번 변경의 필수 배포
1. 한글 Lore 커밋으로 변경 근거와 검증 범위를 남긴다.
2. `gh-pages` 브랜치를 `origin`에 푸시한다.
3. `deploy-gh-pages.yml`의 해당 커밋 실행이 성공하는지 확인한다.
4. 운영 관리자 URL에서 새 상단바 마커와 응답 상태를 확인한다.

### Apps Script 수동 업로드 목록
**0건.** 이번 변경에서 `Appsscript/*` 파일은 수정하지 않았다.

단, Pages 배포 워크플로우의 인증 canary가 기존 외부 상태 문제로 실패할 때만 아래를 별도 진단한다.

1. `locationAttendanceV1` 또는 필수 runtime check 실패: 현재 Apps Script deployment에 저장된 코드와 배포 버전을 확인하고, 필요한 경우 같은 deployment를 다시 배포한다.
2. `AUTH_SERVER_SCOPE_MISSING`: Apps Script 편집기에서 `__authorizeExternalRequest()`를 실행하고 권한을 승인한 뒤 같은 deployment를 다시 배포한다.
3. 새 deployment를 만들어 `.../exec` URL이 바뀐 경우: GitHub Actions Secret `APPS_SCRIPT_WEB_APP_URL`을 새 값으로 갱신하고 Pages를 다시 배포한다.

위 세 항목은 조건부 복구 절차다. 레포만으로 GitHub Secret의 실제 값, Apps Script 콘솔의 현재 배포 선택, 권한 승인 상태를 본 것처럼 단정하지 않는다.

## 8. 롤백 기준
- Pages 배포 후 상단바가 로드되지 않거나 인증 화면이 깨지면 직전 정상 Pages artifact 또는 직전 커밋으로 되돌린다.
- 이번 변경은 Apps Script를 수정하지 않으므로 UI 롤백 때문에 Apps Script deployment를 되돌릴 필요는 없다.
- 이후 탭을 추가할 때는 단일 `#adminTabNav`, ARIA 연결, `admin_compact_layout_test.js`를 함께 갱신한다.
