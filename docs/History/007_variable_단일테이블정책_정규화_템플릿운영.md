## 1. 배경(어떤 이유로 추가됐는지)
운영 중 가장 큰 장애 원인은 `variable` 시트 구조가 혼재된 상태로 사용된 점이었다.

- 레거시(`A2:C2`, `A5:F`)와 신규(`A:I`)가 동시에 존재
- 동일 키 중복행이 누적되어 조회 때마다 값이 달라짐
- number 타입에 `0:00` 같은 시간형 오염값이 들어가 계산이 흔들림
- UI 메타(`applies_to`, `applies_when`)가 비어 `-` 또는 `미정`으로 노출

이 문제는 단순 표기 오류가 아니라 운영 정책 자체를 불안정하게 만드는 이슈였다. `variable`은 출석 오픈 시각, 지각 판정, 수료 계산 같은 핵심 규칙의 단일 입력원이어야 하는데, 동일 키가 여러 행으로 존재하면 “어떤 값이 실제 계산에 쓰였는지”를 운영자가 설명할 수 없게 된다. 실제로 중복행이 누적되던 시점에는 관리자 화면을 열기만 해도 값이 달라 보이는 현상이 보고되었다.

이 문제를 해결하기 위해 `variable`을 단일 정본 테이블로 고정하고, 읽기/쓰기 경로를 분리했으며, 정규화/템플릿 복구 액션을 운영 도구로 제공했다.

## 2. 사용자 절차(어떻게 사용하는지)
### 2-1. 운영자가 평소에 하는 작업
1. 관리자 페이지 `변수명 관리` 탭 진입
2. `value` 컬럼만 수정
3. `변수 저장` 클릭
4. 필요 시 `다시 불러오기`로 서버 반영 확인

이 절차에서 중요한 점은 운영자가 정책값(`value`)만 다루고, 구조/메타는 시스템이 보호한다는 것이다. 운영자가 메타 필드를 직접 수정하면 단기적으로는 편해 보일 수 있지만, 이후 API 호환성과 검증 로직이 깨질 확률이 높다. 따라서 일상 운영은 “값 조정”, 구조 변경은 “템플릿/정규화 액션”으로 역할을 분리한다.

### 2-2. 이상 데이터 정리 절차
1. 동일 키 중복행, `0:00` 오염, 메타 누락이 보이면 `정규화` 실행
2. 그래도 메타가 비면 `템플릿 복구(value 유지)` 실행
3. 정책 자체를 초기값으로 되돌릴 때만 `템플릿 완전 초기화` 실행

정규화와 초기화를 분리한 이유는 운영 리스크를 줄이기 위해서다. 대부분의 장애는 값 자체가 아니라 중복/형식 오염에서 발생하므로, 우선 정규화로 구조만 바로잡고 값은 보존하는 것이 안전하다. 완전 초기화는 정책 리셋을 의도한 경우에만 사용해야 한다.

### 2-3. 구글시트 표준 스키마
정본 스키마는 `A1:I1`이다.

| 컬럼 | 의미 | 운영자 편집 여부 |
|---|---|---|
| `key` | 변수 키(고정) | 불가 |
| `value` | 실제 계산값 | 가능 |
| `type` | `number`/`string` | 불가 |
| `description` | 변수 설명 | 불가 |
| `editable` | 수정 가능 여부 | 불가 |
| `updated_at` | 마지막 갱신시각 | 시스템 입력 |
| `applies_to` | 적용 위치 설명 | 템플릿 관리 |
| `applies_when` | 적용 시점 설명 | 템플릿 관리 |
| `used_in` | 코드 사용처/탭 매핑 근거 | 템플릿 관리 |

표준 CSV는 `docs/History/variable_template_v3_5.csv`를 사용한다.

## 3. 설계 의도(왜 이렇게 했는지)
### 읽기-쓰기 분리
조회 API가 시트를 수정하면 “조회만 했는데 데이터가 변하는” 사고가 반복된다. 그래서 `variablesGet`는 완전 read-only로 고정했다.

### value-only 편집
운영자가 실수로 키/타입/메타를 바꾸면 계산식 자체가 깨진다. 따라서 운영 UI에서는 `value`만 수정 가능하게 제한했다.

### 템플릿 중심 메타 보강
메타가 비어 있어도 즉시 `-`로 노출하지 않고, 시트값 -> 템플릿값 -> 안내문구 순으로 보강해 운영 가독성을 확보했다.

결과적으로 변수 정책의 목표는 “유연성”이 아니라 “예측 가능성”이다. 운영자가 어떤 값을 바꾸면 어떤 계산에 반영되는지 일관되게 설명 가능해야 하고, 조회 행동이 데이터를 오염시키지 않아야 한다. 이 원칙이 지켜져야 수료 판정이나 유고 처리 결과를 신뢰할 수 있다.

## 4. API/데이터 영향
| API | 역할 | 핵심 입력/출력 |
|---|---|---|
| `variablesGet` | 변수 조회(read-only) | `items[]`에 camel/snake 메타, `usedTabsText` 포함 |
| `variablesUpdate` | 값 업데이트 | `value` 변경만 허용, number 검증 강화 |
| `variablesNormalize` | 중복/오염 정리 | `duplicateRemovedCount`, `invalidValueDroppedCount` 등 반환 |
| `variablesResetTemplate` | 템플릿 복구/초기화 | `mode=preserve|reset` |
| `apiInfo` | 백엔드 호환성 확인 | `supportedActions`, `apiVersion`으로 탭 차단 여부 판단 |

정규화 기준은 다음 우선순위를 따른다.

1. 유효값 우선(number에 시간형 문자열 제외)
2. `updated_at` 최신 우선
3. 동률이면 기존 순서 유지

## 6. 운영상 주의점
- `variable` 시트에서 운영자가 직접 행을 복사/붙여넣기하면 중복 키가 다시 생길 수 있다.
- `default_session_start_time`은 `HH:mm` 문자열만 허용한다.
- number 변수에 `:`가 포함되면 저장이 차단되어야 정상이다.
- 템플릿 복구는 메타를 복원하는 기능이며, 값 정책까지 바꾸려면 완전 초기화를 사용해야 한다.

운영 중 긴급 수정이 필요해도 Google Sheets에서 직접 여러 행을 복제하는 방식은 피하는 것이 좋다. 가장 안전한 경로는 관리자 페이지에서 `value`만 수정하고, 이상 징후가 보이면 정규화를 먼저 실행해 데이터 형태를 고정하는 방식이다.

## 7. 검증 시나리오
1. 변수 탭 진입을 10회 반복해도 행 수가 늘지 않는지 확인한다.
2. `attendance_open_offset_min` 등에 `0:00` 입력 시 저장이 거부되는지 확인한다.
3. `default_session_start_time=19:00` 저장 후 조회에서 Date 문자열로 깨지지 않는지 확인한다.
4. `variablesNormalize` 2회 연속 실행 시 두 번째 실행에서 추가 변경이 없는지(idempotent) 확인한다.
5. `applies_to`, `applies_when`, `usedTabsText`가 `-` 없이 렌더되는지 확인한다.

## 8. 실제 운영 사례(실패 예시/대응 예시)
### 사례 1. 변수 탭 진입만으로 시트 행이 늘어난 경우
실패 상황: 운영자가 변수 탭을 여러 번 열자 동일 키(`attendance_open_offset_min` 등)가 반복 생성됐다.  
원인: 구버전 조회 경로에서 레거시 분기를 읽으면서 write side-effect가 발생했다.  
대응: `apiInfo`로 지원 액션을 먼저 확인해 구버전이면 변수 탭을 차단하고, 최신 배포 후 `variablesNormalize`를 1회 실행해 정리했다.  
재발 방지: 조회 API는 read-only 원칙을 코드 리뷰 체크 항목으로 고정했다.

### 사례 2. `default_session_start_time`가 `Sat Dec 30 1899 ...`로 보인 경우
실패 상황: 시트에는 `19:00`이 있는데 UI에서는 Date 문자열로 표시됐다.  
원인: 시트 값이 시간 셀 타입으로 저장되어 문자열 정규화 전에 렌더링됐다.  
대응: 저장/조회 경로에서 `HH:mm` 강제 정규화를 적용하고, 타입이 `string`인 기본 정책을 문서와 템플릿에 명시했다.  
재발 방지: 운영자가 셀 서식을 임의로 시간/날짜 타입으로 바꾸지 않도록 시트 서식 가이드를 운영 문서에 추가했다.

## 9. 남은 리스크/차기 개선 포인트
- 현재 변수 스코프는 전 시즌 공통이다. 시즌별 변수 정책이 필요하면 스코프 키(시즌) 도입이 필요하다.
- 변수 변경 이력 감사(누가 언제 무엇을 바꿨는지)는 시트 `updated_at`만으로 부족할 수 있다.
- 대규모 운영을 위해서는 변수 변경 승인 워크플로우(초안/승인/반영)가 필요할 수 있다.
