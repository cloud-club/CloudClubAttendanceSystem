## 1. 목적과 사용 트리거
이 문서는 관리자 Google 로그인 장애를 운영자가 수동으로 복구할 때 사용하는 표준 런북입니다.

아래 증상 중 하나라도 보이면 이 문서를 기준으로 복구합니다.

1. `Error 401: invalid_client` + `no registered origin`
2. 관리자 로그인 직후 `AUTH_SERVER_SCOPE_MISSING`
3. `UrlFetchApp.fetch` 권한 오류
4. Super/Admin/User 구분 전에 공통 실패

핵심 원칙은 원인 분리입니다.

1. Origin/Consent 문제 (Google Cloud 설정)
2. Apps Script 배포 실행 주체/권한 승인 문제
3. 관리자 등록 정책 문제 (`_admins`)

## 2. 빠른 원인 분리 맵
| 관측 증상 | 1차 원인 후보 | 우선 조치 |
|---|---|---|
| `invalid_client`, `no registered origin` | OAuth Client Origin 누락/불일치 | Google Cloud Console의 `Authorized JavaScript origins` 확인 |
| `AUTH_SERVER_SCOPE_MISSING` | Apps Script `script.external_request` 미승인 또는 잘못된 배포 실행 주체 | `__authorizeExternalRequest()` 실행 + 동일 배포 재배포 |
| `AUTH_ADMIN_NOT_REGISTERED` | `_admins` 또는 최신 시즌 운영진 동기화 정책 | `_admins`/시즌 시트 `운영진 여부`, `Email` 점검 |
| `AUTH_ADMIN_INACTIVE` | 관리자 계정 비활성 상태 | `_admins.is_active` 점검 |
| `Cross-Origin-Opener-Policy...postMessage` | GIS iframe 경고(비장애) | 참고 로그로만 처리, API 에러 코드 기준 판단 |

## 4. 표준 복구 시퀀스 (Gate 방식)
아래 Gate는 순서를 바꾸지 않습니다. 선행 Gate 실패 시 다음 단계로 넘어가지 않습니다.

### Gate 0. 운영 기준점 고정
1. 운영 관리자 페이지의 `env.js`에서 `API_BASE_URL` 확인
2. 복구 대상 `exec` URL을 단일 진실원으로 고정

통과 기준:
- 운영 기준 `exec` URL이 1개로 고정됨

### Gate 1. OAuth Origin/Consent 확인
1. Google Cloud Console에서 Web Client의 `Authorized JavaScript origins` 확인
2. Consent screen이 Testing이면 운영 계정을 Test users에 포함

통과 기준:
- Origin/Consent 설정이 운영 도메인/계정과 일치

### Gate 2. Apps Script 배포 일치 확인
1. `Deploy > Manage deployments`에서 운영 `exec` URL과 동일한 배포 선택
2. `Execute as`, `Who has access` 확인

통과 기준:
- 운영 URL과 배포 설정 일치

### Gate 3. `__authorizeExternalRequest()` 실행 및 권한 승인
1. `Code.gs`의 debug helper `__authorizeExternalRequest()` 실행
2. 권한 승인 팝업 완료

통과 기준:
- 권한 승인 완료(함수 성공/실패 자체보다 승인 팝업 완료가 중요)

### Gate 4. 동일 배포 재배포
1. Gate 2에서 확인한 같은 deployment를 `Edit > Deploy`

통과 기준:
- 재배포 완료 + 대상 URL 일치

### Gate 5. GitHub Secret 반영 + Pages 재배포
1. `APPS_SCRIPT_WEB_APP_URL`를 최신 `exec`로 저장
2. `Deploy GitHub Pages` 워크플로우 실행

통과 기준:
- 워크플로우 성공 + 웹 런타임에 최신 URL 반영

### Gate 6. Canary 통과 확인
1. 로컬 canary 실행:
```bash
scripts/auth_canary_snapshot.sh "https://script.google.com/macros/s/<DEPLOYMENT_ID>/exec"
```
2. 또는 직접 호출:
```text
<exec>?api=authGoogleLogin&idToken=dummy&callback=cb&_={timestamp}
```

통과 기준:
1. `AUTH_SERVER_SCOPE_MISSING`가 아님
2. 기대 코드는 `AUTH_ID_TOKEN_VERIFY_FAILED` 또는 `AUTH_ID_TOKEN_PAYLOAD_INVALID`

### Gate 7. 계정별 시나리오 검증
1. SuperAdmin: 관리자 진입 성공
2. Admin: 로그인 성공 + 시즌 범위 제한
3. User: 로그인 후 `AUTH_ADMIN_NOT_REGISTERED`로 거절

통과 기준:
- 역할별 분기가 의도대로 다르게 동작

## 5. `__authorizeExternalRequest()` 운영 규정 (debug helper)
- 위치: `Code.gs`
- 용도: Apps Script Web App 런타임의 `script.external_request` 권한 승인 트리거
- 실행 조건: `AUTH_SERVER_SCOPE_MISSING` 또는 `UrlFetchApp.fetch` 권한 오류 재현 시
- 기대 결과:
1. 권한 승인 팝업 완료
2. 동일 deployment 재배포 후 canary 코드가 scope 오류가 아니어야 함
- 재실행 기준:
1. 배포 실행 주체 변경 후
2. 새 deployment 생성 후
3. 동일 장애 재발 시

주의:
1. 이 함수는 인증 복구용 debug helper이며 사용자 경로에서 직접 호출되지 않습니다.
2. 실행 후에도 Gate 4~6을 반드시 완료해야 복구가 반영됩니다.

## 6. 에러 코드 기반 의사결정 트리
```text
[시작] 관리자 Google 로그인 실패
  |
  |-- OAuth 에러 URL에 invalid_client/no registered origin 존재?
  |      |-- Yes -> Gate 1 (Google Cloud Origin/Consent)
  |      |-- No
  |
  |-- API code == AUTH_SERVER_SCOPE_MISSING ?
  |      |-- Yes -> Gate 2 -> Gate 3 -> Gate 4 -> Gate 6
  |      |-- No
  |
  |-- API code == AUTH_ADMIN_NOT_REGISTERED 또는 AUTH_ADMIN_INACTIVE ?
  |      |-- Yes -> _admins/season 운영진 데이터 점검
  |      |-- No
  |
  |-- 콘솔에 COOP/postMessage 경고만 존재?
         |-- Yes -> 참고 로그, 기능 장애 아님
         |-- No -> 네트워크/배포/코드 회귀로 분기 조사
```

## 8. 롤백 절차
복구 실패 또는 신규 회귀 발생 시 아래 순서로 롤백합니다.

1. 이전 정상 `exec` URL 확인
2. GitHub Secret `APPS_SCRIPT_WEB_APP_URL`를 이전 값으로 복구
3. GitHub Pages 워크플로우 재실행
4. canary 재검증
5. 필요 시 Apps Script에서 이전 버전으로 재배포

롤백 완료 기준:
- canary 통과
- Super/Admin/User 기본 시나리오 복구
