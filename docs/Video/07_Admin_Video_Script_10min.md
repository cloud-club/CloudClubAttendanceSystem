# Admin Video Script (10min)

> 문서 링크: [docs/Video/07_Admin_Video_Script_10min.md](./07_Admin_Video_Script_10min.md) | [GitHub](https://github.com/cloud-club/CloudClubAttendanceSystem/blob/gh-pages/docs/Video/07_Admin_Video_Script_10min.md)

## 빠른 흐름도
```mermaid
flowchart LR
  A["목적/구조"] --> B["운영 포인트"]
  B --> C["9개 탭 실습"]
  C --> D["데이터 저장 위치"]
  D --> E["마감 루틴"]
```

## 영상 목적
이 영상은 신규 운영진 인수인계를 위해, 관리자 관점의 실사용 흐름과 운영 판단 기준을 10분 안에 보여주는 실습형 스크립트입니다.

## 고정 촬영 조건
- 언어: 한국어
- 러닝타임: 10분
- 시청자: 신규 운영진/유지보수 담당
- 관리자 URL: `https://cloud-club.github.io/CloudClubAttendanceSystem/web/admin/`
- 권한 모델 설명 기준: `user / season_admin(admin) / super`
- 권한 판정 기준: `ACTION_ACCESS_LEVELS`
- 데이터 노출 정책: 실데이터 노출 허용(내부 공유 전제)

## 프리프로덕션 (운영자 영상)
1. `super` 권한 계정으로 로그인 가능한지 먼저 확인합니다.
2. 관리자 페이지에서 9개 탭이 모두 보이는지 확인합니다.
3. 시즌 선택 드롭다운을 촬영용 시즌으로 고정합니다.
4. Google Sheets 접근 권한(시즌 시트, `_admins`, `variable`, `_session_meta`, `_import_meta`)을 사전 확인합니다.
5. 수동 승인/일정 수정 시연을 위해 데모 대상 회원/회차를 1~2건 준비합니다.

## 씬별 대본 (10:00)

### Scene 1 (00:00-00:30) - 목적 선언
- 화면 조작문:
1. 관리자 메인 화면 첫 진입
2. 상단 헤더와 탭 네비가 보이도록 화면 고정
- 내레이션:
"이 영상은 관리자 인수인계를 위한 실사용 가이드입니다. 버튼 설명보다 운영 판단 기준을 중심으로 설명하겠습니다."
- 컷 전환:
탭 네비 전체가 들어오면 컷

### Scene 2 (00:30-01:20) - 인프라 구조 설명
- 화면 조작문:
1. 문서(README) 구조 다이어그램 노출
2. 다시 관리자 화면으로 복귀
- 내레이션:
"현재 구조는 프런트 GitHub Pages, 인증/API Apps Script, 데이터 Google Sheets의 2티어 운영 구조입니다."
- 컷 전환:
관리자 화면 복귀 직후 컷

### Scene 3 (01:20-02:00) - 운영 포인트 설명
- 화면 조작문:
1. 운영 런북 문서 노출
2. 배포 순서 항목을 짧게 포인팅
- 내레이션:
"운영 핵심은 기능보다 순서입니다. Apps Script 배포 후 Secret 반영, Pages 재배포, 그리고 canary 확인 순서로 움직입니다."
- 컷 전환:
배포 순서 문구 확인 후 컷

### Scene 4 (02:00-02:30) - 탭 네비게이션 지도
- 화면 조작문:
1. 9개 탭을 좌→우로 한 번씩 클릭
2. super 전용 탭(변수명 관리, 시즌 생성/업로드, 관리자 관리)을 잠깐 강조
- 내레이션:
"업무는 탭 단위로 보이지만 실제로는 준비-진행-마감 루틴으로 연결됩니다. super 전용 탭은 권한이 없으면 보이지 않습니다."
- 컷 전환:
`관리자 관리` 탭까지 확인 후 컷

### Scene 5 (02:30-03:20) - 출석하기(수동 승인)
- 화면 조작문:
1. `출석하기` 탭 진입
2. `관리자 수동 출석 승인` 영역에서 `승인할 회차` 선택
3. 회원 검색 후 1~2명 선택
4. 필요 시 `관리자 공통 멘트` 입력
5. `수동 승인 실행` 버튼 클릭
- 내레이션:
"현장 누락 복구는 단건이 아니라 배치 승인으로 처리합니다. 덮어쓰기가 필요할 때는 사유를 멘트로 남겨 감사 추적이 가능하게 운영합니다."
- 컷 전환:
결과 요약(`요청/승인/건너뜀/실패`) 표시 후 컷

### Scene 6 (03:20-04:00) - 출석현황
- 화면 조작문:
1. `출석현황` 탭 진입
2. 필터 프리셋 1개 선택 후 `필터 적용`
3. KPI 카드, 차트, 랭킹 영역까지 스크롤
- 내레이션:
"이 탭은 문의 대응 화면이면서 운영 품질 점검 대시보드입니다. 필터를 바꾸면 KPI와 차트, 드릴다운, 랭킹이 함께 갱신됩니다."
- 컷 전환:
랭킹 보드 확인 후 컷

### Scene 7 (04:00-04:40) - 일정 관리
- 화면 조작문:
1. `일정 관리` 탭 진입
2. 날짜/시작시간 입력 후 `일정 추가` 시연
3. 캘린더 보기에서 해당 날짜 포인트
- 내레이션:
"일정 데이터는 출석 판정 기준값입니다. 같은 날짜에 중복 회차를 막는 유일성 정책을 지켜야 이후 출석 계산이 안정적입니다."
- 컷 전환:
일정 저장 결과 메시지 확인 후 컷

### Scene 8 (04:40-05:10) - 유고 처리
- 화면 조작문:
1. `유고 처리` 탭 진입
2. 매트릭스 셀 클릭
3. 유고 사유 입력 후 저장
- 내레이션:
"유고 처리는 예외를 정책 안에서 기록하는 탭입니다. 기존 기록 덮어쓰기 시에는 확인 단계를 거쳐 운영 근거를 남깁니다."
- 컷 전환:
유고 반영 색상/메모 반영 확인 후 컷

### Scene 9 (05:10-05:35) - QR코드 관리
- 화면 조작문:
1. `QR코드 관리` 탭 진입
2. `학생용 Latest QR코드 생성` 실행
3. URL 복사 버튼 클릭
4. 관리자 QR 영역 짧게 확인
- 내레이션:
"학생 URL은 latest 기준으로 고정 안내합니다. 관리자 URL은 운영진 내부에서만 제한적으로 공유합니다."
- 컷 전환:
학생 URL 박스 노출 후 컷

### Scene 10 (05:35-06:05) - 변수명 관리(super)
- 화면 조작문:
1. `변수명 관리` 탭 진입
2. 특정 변수의 `value` 1건 수정
3. `변수 저장` 클릭
- 내레이션:
"정책 조정은 코드 수정이 아니라 value 변경으로 처리합니다. 운영진은 value만 수정하고, 구조 키와 타입은 유지합니다."
- 컷 전환:
저장 완료 메시지 확인 후 컷

### Scene 11 (06:05-06:30) - 수료 판정
- 화면 조작문:
1. `수료 판정` 탭 진입
2. `수료 판정 새로고침` 클릭
3. 요약 카드와 회원별 표를 확인
- 내레이션:
"수료 판정은 출석 데이터, 유고 처리, 변수 정책이 합쳐지는 최종 검증 지점입니다."
- 컷 전환:
회원별 수료 표가 로드되면 컷

### Scene 12 (06:30-07:15) - 시즌 생성/업로드(super)
- 화면 조작문:
1. `시즌 생성/업로드` 탭 진입
2. 파일 선택 후 `파싱/미리보기 분석`
3. `시트 스키마 감사`와 미리보기 화면 확인
- 내레이션:
"업로드는 즉시 반영하지 않고 분석-검증-최종반영 3단계로 운영합니다. blocker가 있으면 finalize를 진행하지 않습니다."
- 컷 전환:
미리보기/감사 리포트 확인 후 컷

### Scene 13 (07:15-07:45) - 관리자 관리(super)
- 화면 조작문:
1. `관리자 관리` 탭 진입
2. 이메일/권한/활성 상태 필드 시연
3. 등록 목록 테이블 확인
- 내레이션:
"권한 경계는 `_admins`를 기준으로 관리합니다. role, season, is_active 조합을 확인하고 변경 후에는 재로그인 검증까지 수행합니다."
- 컷 전환:
등록 관리자 목록 표시 후 컷

### Scene 14 (07:45-10:00) - 데이터 저장 위치 + 운영 마감 루틴
- 화면 조작문:
1. 상단 `Google Sheets 바로가기` 클릭
2. 시즌 시트와 `_admins`, `variable`, `_session_meta`, `_import_meta`를 순서대로 포인팅
3. 관리자 화면으로 돌아와 `출석현황` 및 `수료 판정` 재확인
4. 운영 런북 문서로 마무리
- 내레이션:
"원본은 season 시트, 권한은 `_admins`, 정책값은 `variable`, 세션 보조는 `_session_meta`, 업로드 상태는 `_import_meta`에서 관리합니다. 마감 시에는 결과 재검증과 장애 기록을 남겨 다음 운영자가 같은 기준으로 이어받게 합니다."
- 컷 전환:
런북 문서 화면에서 종료 카드로 페이드아웃

## 9개 탭 3문장 스크립트 템플릿
아래 3문장은 탭 시연 시 반드시 그대로 포함합니다.

### 1) 출석하기
- 접속 방법: "상단 탭에서 `출석하기`를 선택하고 수동 승인 영역으로 이동합니다."
- 핵심 기능: "회차 선택 후 대상자를 다중 선택해 배치 승인으로 누락 출석을 복구합니다."
- 운영 주의: "덮어쓰기는 사유 멘트를 남기고, 결과 요약을 반드시 확인합니다."

### 2) 출석현황
- 접속 방법: "상단 탭에서 `출석현황`을 열고 필터를 설정합니다."
- 핵심 기능: "KPI, 차트, 드릴다운, 랭킹으로 시즌 운영 품질을 함께 점검합니다."
- 운영 주의: "필터 조건이 바뀐 상태에서 수치를 혼동하지 않도록 메타 정보를 함께 확인합니다."

### 3) 일정 관리
- 접속 방법: "상단 탭에서 `일정 관리`를 열고 날짜/시간을 입력합니다."
- 핵심 기능: "회차를 추가/수정/삭제하고 캘린더에서 월간 일정 충돌을 즉시 확인합니다."
- 운영 주의: "동일 날짜 중복 회차는 허용되지 않으며 삭제 전 출석 기록 존재 여부를 먼저 확인합니다."

### 4) 유고 처리
- 접속 방법: "상단 탭에서 `유고 처리`를 열고 대상 회원의 셀을 선택합니다."
- 핵심 기능: "유고 설정/해제를 수행하고 사유 코멘트를 Note로 남깁니다."
- 운영 주의: "기존 출석/지각 기록 덮어쓰기는 확인 단계 후에만 진행합니다."

### 5) QR코드 관리
- 접속 방법: "상단 탭에서 `QR코드 관리`를 열고 학생용 QR 생성 버튼을 누릅니다."
- 핵심 기능: "학생 latest URL과 관리자 URL QR을 생성해 운영 공지 채널에 배포합니다."
- 운영 주의: "학생 안내는 latest 고정, 관리자 URL은 공유 범위를 최소화합니다."

### 6) 변수명 관리 (super 전용)
- 접속 방법: "super 권한 로그인 후 `변수명 관리` 탭에 진입합니다."
- 핵심 기능: "정책 변수의 value를 수정하고 즉시 저장해 운영 기준을 반영합니다."
- 운영 주의: "운영진은 value만 수정하며 key/type 구조는 변경하지 않습니다."

### 7) 수료 판정
- 접속 방법: "상단 탭에서 `수료 판정`을 열고 새로고침을 실행합니다."
- 핵심 기능: "회원별 수료 조건 충족 여부를 표와 요약 카드로 확인합니다."
- 운영 주의: "유고/변수 변경 후 반드시 재산출해 공지 전 결과를 교차 검증합니다."

### 8) 시즌 생성/업로드 (super 전용)
- 접속 방법: "super 권한에서 `시즌 생성/업로드` 탭으로 이동합니다."
- 핵심 기능: "파일 분석, 스키마 감사, diff 확인 후 최종 반영을 수행합니다."
- 운영 주의: "blocker가 남아 있으면 finalize를 진행하지 않고 원인부터 정리합니다."

### 9) 관리자 관리 (super 전용)
- 접속 방법: "super 권한으로 `관리자 관리` 탭에 들어갑니다."
- 핵심 기능: "관리자 이메일, 역할, 활성 상태를 등록/수정/비활성화합니다."
- 운영 주의: "변경 후 실제 로그인 권한 분기를 반드시 재검증합니다."

## 촬영 체크포인트
1. 9개 탭이 모두 영상에 등장하는지 체크합니다.
2. super 전용 탭에서 "권한 없으면 미노출" 멘트를 반드시 포함합니다.
3. 수동 승인과 일정 관리는 실제 조작 컷을 최소 1회 포함합니다.
4. 시트 저장 위치 설명에서 시트명 표기를 정확히 맞춥니다.

## 검증 기준
1. 권한 설명이 `ACTION_ACCESS_LEVELS` 정의와 충돌하지 않아야 합니다.
2. 배포 순서 멘트가 런북 순서와 동일해야 합니다.
3. 탭명/버튼명은 UI 텍스트와 동일해야 합니다.
4. 운영 마감 루틴(재확인 + 기록)이 마지막 씬에 포함되어야 합니다.
