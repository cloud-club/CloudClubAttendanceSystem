# 021 학생 Latest 고정 진입, 과거 시즌 URL 관리자 인증 게이트 적용 기록 (2026-02-20)

## 1. 배경
기존 학생 유입 구조는 `?season=season_nn` 쿼리를 URL에 직접 붙이면 해당 시즌으로 이동 가능한 형태였습니다. 이 방식은 기능적으로 단순했지만 운영 측면에서 아래 문제가 반복됐습니다.

1. 시즌 오유입 위험
- 운영 공지/QR 공유 이후에도 사용자가 수동으로 시즌을 바꿔 접근할 수 있어, 의도하지 않은 과거 시즌 조회가 발생했습니다.
2. 데이터 오인 가능성
- 학생이 최신 시즌이 아닌 페이지에서 출석/상태를 확인하면서 운영 기준과 다른 화면을 보게 되는 사례가 생길 수 있었습니다.
3. 권한 경계 불명확
- 과거 시즌은 운영 검증 성격이 강한데도, URL 구조만으로는 접근 목적(일반 사용자 vs 관리자)을 분리하기 어려웠습니다.

따라서 학생 기본 진입은 항상 Latest로 고정하고, 과거 시즌 URL은 관리자 인증을 통과한 경우에만 허용하는 정책으로 전환했습니다.

## 2. 어떤 변경점이 있었는지
### 2-1. 백엔드 인가 규칙 통합 (`/Users/sbu/SBU/CloudClubAttendanceSystem/Code.gs`)
1. `latestSeason` 액션을 추가해 최신 시즌 alias/번호를 단일 API로 제공했습니다.
2. `session`, `attendance`, `status`, `ranking`의 시즌 해석을 `resolvePublicSeasonAccess`로 통합했습니다.
- `season` 미지정: 최신 시즌 자동 선택
- `season == latest`: 공개 허용
- `season != latest`: `adminToken` 필수 + `requireSeasonAccess` 통과 필수
3. `studentUrl` 액션의 기본 반환을 `/web/student/latest/`로 고정하고, 과거 시즌은 옵션 쿼리(`?season=season_nn`)로만 생성되도록 정리했습니다.

### 2-2. 학생 라우트 canonical 전환
1. 신규 canonical 페이지를 `/web/student/latest/`로 고정했습니다.
2. 레거시 `/web/student/`는 `location.replace` 기반 리다이렉트 전용으로 단순화했습니다.
3. 레거시 query/hash는 유지해 `/web/student/latest/?season=...`로 정규화되도록 했습니다.

### 2-3. 학생 과거 시즌 인증 게이트 도입 (`/Users/sbu/SBU/CloudClubAttendanceSystem/web/student/student.js`)
1. 부트스트랩에서 `latestSeason`을 먼저 조회하고, URL `season`과 비교해 과거 시즌 여부를 판정합니다.
2. 과거 시즌이면 Google GIS 인증 게이트를 노출하고 `authGoogleLogin`으로 관리자 인증을 수행합니다.
3. 관리자 토큰은 요구사항대로 `sessionStorage`(`cc_student_admin_token`)에만 저장합니다.
4. `authSession`으로 세션 복구를 지원하고, 과거 시즌 모드에서만 API에 `adminToken`을 포함합니다.
5. 인증 실패/권한 불일치(`UNAUTHORIZED`, `FORBIDDEN_SEASON`) 시 과거 시즌 요청을 중단하고 `/web/student/latest/`로 자동 복귀합니다.

### 2-4. 랜딩/관리자 UX 정합성 정리
1. 랜딩 학생 링크 기본값을 `/student/latest/`로 고정했습니다.
2. 관리자 QR 기본 생성 URL도 `/student/latest/` 기준으로 정리했습니다.
3. 관리자 화면 문구를 “Latest 기본 진입, 과거 시즌은 관리자 인증 필요” 정책에 맞게 갱신했습니다.

## 3. 왜 변경했는지
이번 변경은 “학생은 최신 시즌으로 안정적으로 유입, 과거 시즌은 관리자 검증 행위로 분리”라는 운영 원칙을 코드/URL/UX 전체에 일관 적용하기 위해 진행했습니다.

1. 시즌 오유입/오기록 리스크 감소
- 학생 기본 유입을 Latest로 고정해 운영 공지/QR과 실제 진입 경로를 일치시켰습니다.
2. RBAC 경계 강화
- `season_admin`은 본인 시즌만, `super`는 전 시즌 허용이라는 기존 권한 모델을 과거 시즌 URL에도 동일 적용했습니다.
3. 우회 경로 포함 정책 수렴
- 프런트 라우팅뿐 아니라 직접 API 호출까지 동일 인가 규칙으로 통제하도록 백엔드 해석 규칙을 통합했습니다.
