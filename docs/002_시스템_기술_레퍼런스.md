## 2. 시트 스키마 v2 계약

### 2-1. 표준 헤더
- A `Name`
- B `Season`
- C `Phone`
- D `Email`
- E `Github ID`
- F `Github Email`
- G `Notion Email`
- H `Discord ID`
- I `Slack Email`
- J `회비 체크`
- K `수료 여부`
- L `운영진 여부`
- M+ 출석 세션 헤더

### 2-2. 세션 헤더 패턴
- `YYYY-MM-DD-HH:MM`
- `YYYY-MM-DD-HH:MM~HH:MM`

### 2-3. 슈퍼키
- 유저 식별은 `Phone` only.
- phone 중복은 자동 병합하지 않으며 API 에러(`PHONE_SUPERKEY_DUPLICATE`)로 반환.

### 2-4. 정규화
- Phone: non-digit 제거 후 `010########`
- Season: `9기`, `season_09`, `9` -> `9`
- Email 계열: trim + lower-case
- boolean: `TRUE/FALSE`, `1/0`, `Y/N`, `O/X`, `예/아니오` 허용

### 3-1. 스키마 해석 레이어
- `resolveMemberSchemaFromHeaders(headers)`
- `resolveMemberSchema(sheet)`

- `normalizeMemberRecord(raw, schema)`

- v1/v2/custom 헤더를 동적으로 해석.

- `markAttendanceInSheet`
- `getAttendanceStatusFromSheet`
- `getAttendanceRankingFromSheet`
- `getMembers`
- `manualApproveAttendance`
- `setExcusedAttendance`
- `getGraduationReport`

### 3-3. import 파이프라인
- `beginSeasonImport`
- `importSeasonChunk`
- `finalizeSeasonImport`

- `getStagingSeenKeys`

변경점:

### 3-4. 스키마 감사 API

## 6. 수동 데이터 전환 가이드 (운영자)

2. 운영 공지 후 30~60분 입력 동결.

6. J~L 체크박스 적용.
7. phone 중복 0건 확인.
8. `sheetSchemaAudit`로 최종 확인.
9. 실제 1건 출석 테스트 후 운영 재개.
