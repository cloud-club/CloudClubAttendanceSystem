# 006 시즌표준화, 참조시트, 관리자 탭 기반 운영

## 1. 배경(어떤 이유로 추가됐는지)
초기 운영에서는 시즌 시트명이 `07`, `08`처럼 숫자 기반이었고, 관리자 화면에서는 별도의 변환 규칙으로 시즌을 표시했다. 이 방식은 다음 문제를 만들었다.

- 운영자가 시트명과 UI 시즌명을 다르게 인식하는 오류 발생
- 학생 URL의 시즌 쿼리(`season`)와 실제 운영 대상 시즌 불일치 가능성
- 다수 시즌 운영 시 참조 시트 전환 실수 증가

표면적으로는 단순 표기 문제처럼 보였지만 실제 영향은 더 컸다. 시즌명이 통일되지 않으면 같은 사용자가 “어제와 같은 시즌에서 작업했다”고 생각해도 실제로는 다른 시트를 참조할 수 있고, QR 공유 시 학생 트래픽이 엉뚱한 시즌으로 분산된다. 운영자가 문제를 인지한 시점에는 이미 잘못된 시트에 출석 데이터가 쓰인 뒤인 경우가 많아, 사후 복구 비용이 매우 높았다.

이를 해결하기 위해 시즌 표기와 실제 시트명을 모두 `season_nn`으로 통일했고, 관리자 상단의 “참조할 시트”를 운영 기준점으로 고정했다.

## 2. 사용자 절차(어떻게 사용하는지)
1. 관리자 페이지 상단 `참조할 시트` 드롭다운에서 운영 대상 시즌(예: `season_09`)을 선택한다.
2. 바로 옆 `Google Sheets 바로가기` 버튼으로 동일 시즌 시트 탭으로 이동해 데이터 원본을 확인한다.
3. `데이터 새로고침`으로 관리자 화면 데이터를 다시 동기화한다.
4. QR코드/출석/일정/유고/수료 탭은 모두 상단에서 고른 시즌을 기준으로 동작한다. 단, 학생 기본 진입 URL은 항상 `/web/student/latest/`를 사용한다.

실무에서는 “작업 전에 시즌 확인, 저장 후 원본 확인”의 두 단계가 중요하다. 이 절차를 고정하면 운영자가 탭을 빠르게 이동해도 현재 작업 맥락을 잃지 않는다. 반대로 이 절차를 생략하면 출석/수료 데이터가 시즌 간 섞이는 사고가 다시 발생할 수 있다.

운영자가 먼저 확인해야 할 값은 “현재 시즌 표시 라벨”과 “드롭다운 선택값”의 일치 여부다.

## 3. 설계 의도(왜 이렇게 했는지)
핵심 의도는 “관리자 입력 실수의 비용을 낮추는 것”이다.

- 시즌명 스키마를 고정해 문자열 변환 비용을 제거했다.
- 시즌 전환 액션을 탭 내부가 아닌 상단 공통 제어로 이동했다.
- 시트 원본 확인 버튼을 상단에 둬 데이터 검증 경로를 짧게 만들었다.

즉, 사용성 개선의 초점이 “더 많은 조작”이 아니라 “더 적은 판단”에 맞춰져 있다. 시즌 관련 판단 지점을 여러 화면에 흩어두면 운영자는 매번 문맥을 복원해야 한다. 이를 상단 공통 영역으로 끌어올리면 운영자가 어떤 탭에 있든 같은 기준점에서 판단하게 되어 실수 빈도가 떨어진다.

즉, 기능을 늘리기보다 기준점을 하나로 묶어 운영 오판을 줄이는 구조다.

## 6. 운영상 주의점
- 시트명을 `season_nn`으로 통일해도 기존 수식/링크가 숫자 시트명(`07`)을 참조하면 깨질 수 있다. 변경 전 링크 점검이 필요하다.
- 관리자 상단 시즌이 바뀐 상태로 다른 탭에서 저장을 누르면 그 시즌에 즉시 반영된다.
- 시트 전환 직후에는 반드시 `데이터 새로고침` 또는 탭 재진입으로 최신 상태를 확인한다.

## 7. 검증 시나리오
1. `season_07`, `season_08`, `season_09` 전환 시 탭 데이터가 정확히 바뀌는지 확인한다.
2. `Google Sheets 바로가기`가 선택 시즌의 정확한 탭(`gid`)으로 이동하는지 확인한다.
3. 관리자 QR 생성 시 학생 URL이 `/web/student/latest/`인지, 과거 시즌 URL은 관리자 인증 게이트가 동작하는지 확인한다.
4. 모바일 화면(375/390/430px)에서 상단 툴바가 2행 컴팩트로 보이는지 확인한다.

## 8. 실제 운영 사례(실패 예시/대응 예시)
### 사례 1. QR은 정상인데 학생이 다른 시즌으로 유입된 경우
실패 상황: 운영자는 `season_09`를 운영한다고 생각했지만 학생 제보에서는 `season_08` 데이터가 보였다.  
원인: 상단 참조 시트를 바꾸기 전에 QR을 생성했고, 이전 시즌 상태로 링크가 만들어졌다.  
대응: 학생 기본 진입을 `Latest` URL로 고정하고, 과거 시즌 URL은 관리자 Google 인증이 없으면 자동으로 최신 시즌으로 돌려보내도록 정책을 강화했다.  
재발 방지: 공지 전 “시즌 확인 -> Latest URL 확인 -> 공유” 3단계 체크를 운영 매뉴얼에 반영했다.

### 사례 2. 시즌명 변경 후 일부 내부 링크가 깨진 경우
실패 상황: 시트명을 `07`에서 `season_07`로 바꾼 뒤 일부 스프레드시트 수식/링크가 실패했다.  
원인: 외부 참조 수식과 내부 문서가 구 시트명을 하드코딩하고 있었다.  
대응: 시즌 표준화 전후 링크 목록을 추출해 일괄 교체하고, `sheetLink` API로 최종 접근 경로를 확인했다.  
재발 방지: 시즌명 정책 변경은 기능 배포와 분리해 사전 점검일에 먼저 수행하고, 변경 당일에는 운영 입력을 최소화했다.

## 9. 남은 리스크/차기 개선 포인트
- 시즌 리스트가 길어지면 드롭다운 탐색성이 떨어질 수 있다. 검색형 시즌 선택 UI가 필요하다.
- 시즌별 운영 로그(누가 언제 시즌을 바꿨는지)가 남지 않는다. 감사 로그 액션이 있으면 운영 추적성이 올라간다.
