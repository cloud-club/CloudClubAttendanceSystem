# 017 관리자 수동출석 배치승인 및 실승인시각 경계보정 운영정책

## 1. 배경(어떤 이유로 추가됐는지)
관리자 수동출석은 운영상 반드시 필요한 기능이지만, 기존 방식은 다음 한계가 있었다.

- 대상자 식별이 단건 중심이라 다수 누락 복구 시 반복 작업 비용이 컸다.
- 수동 승인 시각의 정책이 고정(`lateDeadline`)에 가까워 운영 개입 시점 설명이 어려웠다.
- 승인 흔적은 남았지만, 배치 처리/덮어쓰기/멘트를 한 번에 감사하기에는 정보가 분산되어 있었다.

이번 개선은 최근 2개 커밋(`f1749ec`, `91f36cb`)을 통해 관리자 탭의 수동출석을 배치 처리 중심으로 고도화하고, 기록 시각 정책을 `실제 승인 시각 + 회차 경계보정`으로 전환한 변경을 운영 기준으로 정리한 문서다.

## 2. 사용자 절차(어떻게 사용하는지)
### 2-1. 대상 시즌/회차 선택
1. 관리자 페이지 `출석하기` 탭에서 `관리자 수동 출석 승인` 영역으로 이동한다.
2. 시즌을 선택하고, 승인할 회차를 선택한다.
3. 선택한 회차 기준으로 시트의 회원 목록과 현재 출석 상태를 불러온다.

### 2-2. 다중 선택 및 멘트 입력
1. 대상자를 다중 토글로 선택한다.
2. 필요하면 `관리자 공통멘트`를 입력한다.
3. 회원별로 추가 설명이 필요하면 개별멘트를 입력한다.
4. 기존 값이 있는 셀을 덮어써야 하는 경우에만 `강제 덮어쓰기`를 사용한다.

### 2-3. 배치 승인 실행
1. `수동 승인 배치 처리`를 실행한다.
2. 서버는 선택된 회원을 배치 단위로 처리하고, 각 대상별 승인/건너뜀/실패 결과를 반환한다.
3. 기존 값이 있을 때 `강제 덮어쓰기`가 비활성화되어 있으면 해당 건은 자동으로 `건너뜀` 처리된다.

### 2-4. 기록 시각 및 메모 확인
1. 기록 시각은 승인 버튼을 누른 실제 시각을 기본으로 사용한다.
2. 실제 시각이 회차 오픈 전이면 `openTime`으로, 회차 마감 후면 `lateDeadline`으로 자동 보정한다.
3. 원본 셀 Note에는 처리일시, 기록시각, 경계보정 여부, 공통/개별멘트, 덮어쓰기 이력이 저장된다.
4. 관리자 화면 결과표에서 `기록시각` 열과 보정 라벨(오픈시각 보정/마감시각 보정)을 확인한다.

## 3. 설계 의도(왜 이렇게 했는지)
### 운영 처리량 개선
대량 누락 복구 상황에서 단건 승인 반복을 줄이기 위해 다중 선택 배치 처리를 기본 UX로 두었다.

### 공정성과 설명 가능성 동시 확보
임의 시각 입력을 허용하지 않고 승인 클릭 시각을 기준으로 기록하되, 회차 경계를 벗어난 시각은 자동 보정해 판정 일관성을 유지했다.

### 감사 추적 강화
셀 Note에 처리 맥락(처리 시각, 실제 승인 시각, 멘트, 덮어쓰기 이전 상태)을 남겨 사후 검토 시 근거를 재현할 수 있도록 했다.

## 4. API/데이터 영향
| API/영역 | 변경 내용 | 운영 규칙 |
|---|---|---|
| `manualApprove` | 기록시각 정책 변경, 응답 필드 확장 | 실제 승인 시각 사용 + 회차 경계 보정 |
| `manualApproveBatch` | 배치 결과 상세 필드 확장, 시간정책 통일 | 대상별 결과/기록시각/보정사유 반환 |
| `computeManualApprovalWriteTime` | 승인시각 산정 로직 신설 | `before_open -> openTime`, `after_close -> lateDeadline` |
| 셀 Note(`buildManualApproveNoteText`) | 메모 포맷 확장 | 처리일시/기록시각/보정정보/멘트/덮어쓰기 이력 기록 |
| 관리자 결과표(`renderManualApproveDetailTable`) | `기록시각` 열 추가 | 보정 시 라벨 노출로 운영자가 즉시 판별 |

주요 응답 필드(신규/강화):

- `writtenAt`: 보정 반영 후 실제 셀에 기록된 시각 문자열
- `actualApprovedAt`: 관리자 승인 클릭 시각
- `boundaryAdjusted`: 경계 보정 여부
- `boundaryAdjustReason`: `before_open`, `after_close`, `none`
- `timePolicy`: `actual_click_with_clamp`
- `attendanceType`: 보정된 기록시각 기준 판정값

## 6. 운영상 주의점
- 배치 승인 전 회차 선택이 정확한지 먼저 확인한다(다른 회차에 기록되면 복구 비용이 크다).
- 기존 값 덮어쓰기는 판정 결과를 바꾸므로 `강제 덮어쓰기` 사용 시 사유를 멘트로 남긴다.
- `boundaryAdjusted=true` 건은 운영 검토 대상로 분류해, 회의록/공지 근거와 함께 관리한다.
- 승인 후에는 출석현황/수료판정 탭을 새로고침해 집계 반영을 즉시 확인한다.

## 7. 검증 시나리오
1. 회원 3명 이상을 선택해 배치 승인 시 `요청/승인/건너뜀/실패` 요약이 실제 결과와 일치하는지 확인한다.
2. 기존 기록이 있는 회원을 `강제 덮어쓰기=false`로 실행했을 때 `건너뜀` 처리되는지 확인한다.
3. 동일 조건에서 `강제 덮어쓰기=true`로 재실행 시 승인되고 이전 기록 요약이 Note에 남는지 확인한다.
4. 회차 오픈 전 승인 시 `writtenAt=openTime`, `boundaryAdjustReason=before_open`으로 기록되는지 확인한다.
5. 회차 마감 후 승인 시 `writtenAt=lateDeadline`, `boundaryAdjustReason=after_close`로 기록되는지 확인한다.
6. 회차 경계 내부 승인 시 `writtenAt=actualApprovedAt`로 기록되는지 확인한다.
7. 관리자 결과표의 `기록시각` 열에 보정 라벨이 함께 표시되는지 확인한다.
8. 셀 Note에 처리일시/기록시각/공통멘트/개별멘트/처리결과(신규·덮어쓰기)가 모두 남는지 확인한다.

## 8. 실제 운영 사례(실패 예시/대응 예시)
### 사례 1. 대량 누락 복구가 지연된 경우
실패 상황: 행사 당일 네트워크 이슈로 누락자가 다수 발생했는데 단건 승인 반복으로 복구가 지연됐다.  
원인: 운영자가 한 번에 여러 대상을 처리할 수 있는 UX가 부족했다.  
대응: 배치 선택/승인/결과요약 흐름으로 전환해 대량 처리 시간을 단축했다.  
재발 방지: 운영 체크리스트에 “누락 복구는 배치 승인 우선” 절차를 추가했다.

### 사례 2. 수동 승인 시간 공정성 문의가 발생한 경우
실패 상황: 승인 기록시각이 실제 운영 개입 시점과 다르게 보인다는 문의가 발생했다.  
원인: 기록시각 정책이 사용자 체감과 다르게 해석될 여지가 있었다.  
대응: 승인 클릭 시각을 기본으로 기록하고, 회차 경계 밖만 자동 보정하는 정책으로 전환했다.  
재발 방지: 결과표/Note에 처리일시와 기록시각, 보정 사유를 함께 표기해 설명 가능성을 높였다.

## 9. 남은 리스크/차기 개선 포인트
- 현재 감사 정보는 셀 Note 중심이라 “누가 승인했는지(관리자 식별자)”까지 구조화되지 않는다.
- 대량 처리 실패 건 재시도 시, 실패 원인 코드별 자동 필터/재시도 버튼이 있으면 운영 효율이 더 높아진다.
- 장기적으로는 수동승인 이벤트 로그를 별도 시트/스토리지에 append-only 형태로 적재하는 개선이 필요하다.
