# 016 출석현황 대시보드 필터UX 및 도넛확장 운영정책

## 1. 배경(어떤 이유로 추가됐는지)
출석 현황 페이지는 단순 조회/랭킹에서 운영진 의사결정용 대시보드로 확장되었다.  
초기 확장 후 실제 운영 피드백에서 다음 이슈가 반복됐다.

- 필터 블록이 세로로 길어져 화면 가독성이 떨어짐
- 원형 차트가 토글형 1개일 때 비교 관찰이 어려움
- 전체 인원의 출석 참여 분포(몇 회 출석층이 많은지)를 즉시 보기 어려움

따라서 이번 단계는 기능 추가보다 운영 UX 품질을 높이는 데 초점을 맞췄다.  
결과적으로 대시보드는 **상단 3개 + 하단 3개 차트** 구조로 정리되었고, 필터는 compact + popover 방식으로 재구성되었다.

## 2. 사용자 절차(어떻게 사용하는지)
### 2-1. 필터 조작(운영자)
1. 그룹/기간/Top-N/정렬/차트타입을 기본 필터에서 설정한다.
2. 행사/개인 선택은 `선택` 버튼으로 popover를 열어 체크박스로 고른다.
3. 선택 요약은 배지(`선택 N개`)와 요약 칩(`최대 2개 + +N`)으로 확인한다.
4. `필터 적용`을 누르면 KPI/차트/드릴다운/순위가 동시에 갱신된다.

### 2-2. 차트 해석(운영진)
1. 상단 3개:
   - 행사별 출석률 추이
   - 행사별 출석/지각/결석/유고 분포
   - 개인별 출석 시간 추이
2. 하단 3개:
   - 출석 상태 비율 도넛
   - OB/YB 구성 비율 도넛
   - 출석 횟수 분포 도넛(정확 횟수별 + 기타)

### 2-3. 팝오버 상호작용
- 외부 클릭 또는 `ESC`로 닫힘
- 모바일에서는 하단 고정 패널 형태로 표시

## 3. 설계 의도(왜 이렇게 했는지)
핵심 의도는 “기능 수”가 아니라 “운영자가 빠르게 판단할 수 있는 화면 밀도”다.

- **필터 compact화**: 인라인 대형 리스트를 제거해 초점 영역(차트/지표)을 위로 끌어올림
- **도넛 동시 노출**: 상태/구성/횟수분포를 같은 시점에 비교 가능하게 만듦
- **분포 도넛 도입**: 평균값만으로 보이지 않는 참여층 분포를 드러냄

출석 횟수 분포는 “72명을 전부 나열”하지 않고 `N회 출석` 기준으로 묶어 보여 운영진이 전반적 참여도를 즉시 파악할 수 있도록 했다.

## 6. 운영상 주의점
- 출석 상태 도넛은 종료 회차 기준 집계 특성을 따른다(필터가 과도하면 empty-state가 나올 수 있음).
- 출석 횟수 분포 도넛은 조각 수가 많아질 때 상위 버킷 중심으로 보여주고 나머지는 `기타`로 묶는다.
- 필터 popover를 열어둔 상태로 스크롤할 때 모바일에서 패널 위치가 고정되므로, 의도치 않은 터치 입력을 피하려면 패널을 먼저 닫고 이동한다.
- 운영 보고 시에는 시즌/그룹/기간 필터 스냅샷을 함께 캡처해야 지표 해석이 일관된다.

## 7. 검증 시나리오
1. 데스크톱에서 하단 도넛이 3열로 표시되는지 확인한다.
2. 1200px 이하에서 하단 도넛이 2열, 768px 이하에서 1열로 전환되는지 확인한다.
3. 행사/개인 popover가 외부 클릭 및 `ESC`로 닫히는지 확인한다.
4. 그룹/기간/행사 필터 변경 시 KPI/상단3/하단3/순위/드릴다운이 모두 동시에 갱신되는지 확인한다.
5. 데이터가 없는 조건에서 각 도넛 empty-state 문구가 정상 표시되는지 확인한다.
6. 출석 횟수 분포 도넛 tooltip이 `인원수 + 비율`을 함께 보여주는지 확인한다.

## 8. 실제 운영 사례(실패 예시/대응 예시)
### 사례 1. 필터 화면이 길어 차트 확인이 어려운 경우
실패 상황: 행사/개인 다중선택 블록이 커서 화면 첫 진입 시 차트가 아래로 밀림.  
원인: 인라인 리스트 중심 UI가 대시보드 밀도에 맞지 않았음.  
대응: compact 요약 + popover 선택기로 전환해 기본 화면 높이를 축소.  
재발 방지: 새로운 필터 요소 추가 시 “기본 화면 높이 증가”를 리뷰 체크 항목에 포함.

### 사례 2. 원형 차트 비교가 불편한 경우
실패 상황: 토글형 단일 도넛에서는 상태/구성 비교를 동시 수행하기 어려움.  
원인: 컨텍스트 전환 비용(토글 클릭)이 반복됨.  
대응: 하단 도넛을 동시 노출(상태/OBYB/횟수분포)로 재배치.  
재발 방지: 운영 핵심 지표는 가능한 한 “동시 가시성” 기준으로 배치.

### 사례 3. 출석률은 보이는데 참여층 분포가 안 보이는 경우
실패 상황: 평균/비율만으로는 참여 편중(저참여층 누적)을 빠르게 파악하기 어려움.  
원인: 집단 분포 차트 부재.  
대응: 출석 횟수 분포 도넛을 추가해 `N회 출석 인원`을 즉시 확인 가능하게 함.  
재발 방지: 차기 지표 추가 시 평균값 + 분포값을 함께 검토.
